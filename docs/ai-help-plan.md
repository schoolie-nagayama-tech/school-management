## 0. 何をするか

いまのヘルプは **162項目の静的FAQ**（`FAQ_DATA`）をキーワードで絞り込む方式。
項目が増え続け、「どの項目に書いてあるか分からない」「言い回しが違うと引っかからない」に当たっている。

**質問を日本語で打つと、該当するFAQを見つけて、その内容だけで答える。** 新しい知識は作らない。
FAQに無いことは **「載っていません」と言って黙る**。

## 1. なぜ最初に実装するか（2026-09-03 ユーザー判断）

1. **個人情報を一切送らない。** AIに渡すのは FAQ本文・質問・ロール・いまのページのパスだけ。
   生徒のデータはどこにも触れない。AI機能11個のうち、これだけが**設計上そう**なっている。
2. **社内だけが読む。** 間違えても保護者には届かない。
3. **材料がすでに揃っている。** 機能追加のたびにFAQを書き足す運用を続けてきたので、
   手順つきの本文が162項目ある（`path` 140・`steps` 140・`link` 89・`roles` 140）。
4. **共通土台（`/api/ai/**`）の最初の利用者として最適。** データの秘匿が要らないぶん、土台の配線だけを検証できる。

★プライバシーポリシー第5条は **ちーがるチェック中のため改訂しない**（2026-09-03）。
本機能は個人情報を送らないので、改訂を待たずに出せる可能性がある。**ここは確認してから**。

## 2. 置く場所（新規画面はゼロ）

| どこ | 何を足すか |
| --- | --- |
| `/help` の最上部 | 入力欄「何に困っていますか」。既存の検索欄の**上**に置く。検索欄は残す |
| `ContextHelp`（10ページに設置済み） | ポップオーバーに「このページについて聞く」の入力欄。いまのパスを添えて同じAPIを呼ぶ |

答えの見せ方は両方同じ。

```
[答え]  2〜4文。手順があれば番号つきで
[該当ページを開く →]   （FAQの link.href があるときだけ）
[元のFAQ]  使った項目を既存の描画のまま展開（question / answer / path / steps / tips）
[役に立った] [立たなかった]
```

## 3. 仕組み: 2段階

`FAQ_DATA` は **143,000字**。全部を毎回渡すには大きすぎる。2回に分ける。

### 3-1. 絞り込み（どの項目か）

- 渡すもの: 全項目の **見出しだけ**（id・カテゴリ・question・keywords）。約1万トークン。
  **プロンプトキャッシュに載せる**（内容は静的なので毎回同じ）。
- 返すもの: 該当しそうな項目の id を**3つまで**。無ければ空。
- ★**ロールで先に除く。** 講師には admin/manager 専用の項目を**見出しごと渡さない**。
  サーバー側で `roles` を見て落とす。存在自体を知らせない。
- いまのページのパスと `link.href` が一致する項目は先頭に置いて優先させる。

キーワード検索でなくAIに選ばせるのは、**言い回しの違いを吸収する**ため（ここが静的FAQの限界だった）。

### 3-2. 答える

- 渡すもの: 選ばれた項目の**全文**（question / answer / path / steps / tips / link）、
  用語集（`GLOSSARY_DATA`・15語・2,300字）、質問、ロール、いまのページ。
- 返すもの（JSON）:

```json
{
  "answer": "2〜4文の答え",
  "steps": ["手順があれば FAQ の steps をそのまま"],
  "used": ["faq-id"],
  "page": { "href": "/students", "label": "生徒管理を開く" },
  "unanswered": false
}
```

### 3-3. AIに守らせること（プロンプトに固定）

- **FAQに書いてあることだけで答える。** 書いていない操作・画面・設定を作らない。
- **手順は `steps` を写す。言い換えない。** 順番を変えない、省かない。
- **載っていなければ `unanswered: true` で黙る。** 「たぶんこうです」を書かない。
  塾の運用を誤って案内すると事故になる。
- **業務判断には答えない。**「この生徒は退塾扱いにすべきか」のような問いは、操作の質問ではないので `unanswered`。
- 2〜4文。です・ます調。読むのは講師と教室長。

## 4. 答えられなかった質問を、FAQを書く材料にする

これが運用の要。

- 質問・ロール・パス・選ばれた id・`unanswered`・「役に立った/立たなかった」を **`help_questions`** に記録する。
- `/help` に **admin 限定の「答えられなかった質問」一覧**を出す。
- 教室長・admin はこれを見て FAQ を書き足す（[[進め方_機能変更時にヘルプ更新]] の運用に乗る）。
  書き足せば次から答えられる。**AIを賢くするのではなく FAQ を育てる。**

入力欄には「生徒名は書かないでください」を添える（記録に残るため）。

## 5. 実装メモ

- **`FAQ_DATA` を `src/lib/help/faqData.ts` に出す。** いまは 4,364行の client page の中にあり、
  `icon`（LucideIcon）を持っているのでサーバーから import できない。データと icon の対応を分ける。
- **各項目に安定した id を付ける**（カテゴリ id ＋ スラッグ）。引用と記録に使う。
  いまは `question` の文字列でクロスリンク（`related`）しているので、その置き換えも兼ねる。
- Route Handler は `/api/ai/help`（共通土台 §5 の1本目）。認証は `getApiAuth`、ロールはそこから取る。
- モデルは Haiku。3-1 の見出し一覧はキャッシュ。1問あたり **1円未満**。
  1,000問/月でも数百円。

## 6. 決めたこと / 決めないこと

| | |
| --- | --- |
| 画面遷移まで案内するか | **する。** `link.href` があるときだけ「該当ページを開く」を出す。無ければ出さない |
| ロール別の出し分け | **する。** 見出しの段階で除く（3-1） |
| 答えられないとき | **黙る。** `unanswered` を返し、既存のキーワード検索の結果を代わりに出す |
| 会話を続けるか | **続けない。** 1問1答。追加で聞きたければ打ち直す（会話状態を持たない） |
| 保護者向けヘルプ | **対象外。** 社内のみ |

## 6-2. 鍵の設定でハマったところ（2026-09-04）

★**「すべてのワークスペース」に紐づく鍵（コンソールのタイプ=個人）は、対象ワークスペースの指定が要る。**
指定しないと全リクエストが 400 で落ちる:

```
anthropic-workspace-id is required when authenticating with an identity-linked API key;
send the id of the workspace this request acts in.
```

直し方は2つ。どちらでもよい。

| 方法 | やること |
| --- | --- |
| 環境変数を足す | Vercel に `ANTHROPIC_WORKSPACE_ID` を追加（コンソールの Settings → Workspaces でIDを確認）。いまの鍵をそのまま使える |
| 鍵を作り直す | コンソールで**ワークスペースを1つ指定した鍵**を新しく作り、`ANTHROPIC_API_KEY` を差し替える。環境変数は増えない |

★**切り分けは `GET /api/ai/help/diagnose`（admin限定）で行う。** 最小の呼び出し／キャッシュ付き／Sonnet を
順に試し、失敗した理由の原文をそのまま返す。今回はこれで一発だった。

★**プロンプトキャッシュが組織で無効でも動く。** 400で弾かれたらキャッシュを外して1回だけ再試行する。
有効にしたほうが費用と速度は改善するので、コンソールで有効にするのは推奨。

- admin 限定「答えられなかった質問」一覧。
