## 0. 何をするか

今の高校マスタ（`high_schools` ＋ `high_school_standards`）は、所在地・沿線・合格めやすまで。
面談で生徒と保護者が実際に気にするのはその先で、**部活・制服・進学実績・雰囲気**。
教室長としては**校舎の改築や制服の変更**のような「学校の変化」も知っておきたい。
これを、出典つきで学校ごとに溜める。

## 1. 決めたこと（2026-09-23）

1. **使い道は面談とAIヘルプ。** おすすめ校の自動提案は今回の目的に入れない。
2. **範囲は通塾圏。** 各教室の最寄駅から直線10km圏の公立（都立48校＋神奈川37校＝85校）に、
   教室長が足す学校（例：西・湘南・川和・横浜緑ケ丘のような、遠くても目指す上位校）を加える。
   教室の都県の公立だけ。直線距離は今の最寄駅と同じく「目安」で、通学の実態ではない。
3. **埼玉は入試制度だけ。** 清瀬校の生徒が埼玉県立を受けうるため。学校ごとのデータは持たない。
   入試制度は別セッションで vault とAIヘルプに入れる。
4. **男女比は「出ている学校だけ」。** 男女合同募集になってから、公式に出さない学校が多い
   （松が谷はパンフに載せている・日野は出していない）。空で構わない。
5. **部活の強さは「都立（県立）の中での位置」で4段階。** 全国に出たかどうかではない。§3
6. **進学実績は、数に「方式」と「指定校」を添える。** 中堅校の GMARCH はほぼ指定校なので、
   数だけ出すと誤解を生む。方式別・指定校一覧は、出している学校だけ。
7. **野球の試合結果は一球速報.com を使ってよい。** 東京都高野連のサイトは接続できなかった。

## 3. 部活の強さ（4段階）

| 段階 | 意味         | 判定の目安（案。競技ごとに教室長と詰める）                                                                                    |
| ---- | ------------ | ----------------------------------------------------------------------------------------------------------------------------- |
| 1    | 私立と戦える | 直近3年で、全国・関東大会に出場、または都県大会ベスト8以上が**2回以上**                                                       |
| 2    | 都立の強豪   | 都教委 Premiere Club に指定されている、または都県大会で上位（ベスト8が1回・ベスト16〜32が複数回）、またはその年の都立で最上位 |
| 3    | 普通に活動   | 大会に出ている（上に届かない）                                                                                                |
| 4    | ゆるめ       | 週3日以下で、目立つ大会実績がない                                                                                             |

- ★**段階には必ず根拠（年度・大会・結果・出典）を付ける。** AIの印象で付けると、自信たっぷりに嘘をつく。
- 「強豪ではない所で続けたい」という生徒もいる。3と4を探せるようにするため、**活動日数は強さと別に持つ**。
- 野球の「都県大会」は、夏の東西東京大会と、秋・春の都大会の本大会。一次予選は数えない。
- **サッカー（男子）はリーグの所属で判定する**（2026-09-24 決定）。東京 T1・T2／神奈川 K1・K2＝1、T3・T4／K3・K4＝2、T5・支部リーグ／K5・K6＝3。
  ★T5（約40チーム、国立・日野台・保谷など）は段階3（ユーザー判断）。女子は別リーグなので男女は別の行。手引き §6
- 試しの判定：日野の硬式野球＝2（Premiere Club Tier1、2025年秋の都大会ベスト8で都立最上位。夏は3年とも3回戦まで）、
  松が谷の硬式野球＝3（夏は初戦〜2回戦、秋は一次予選で敗退）。

## 4. 表の形

今の `high_schools`（学校×学科で1行）の上に、**学校単位の親の表**を置く。
部活・進学実績・行事は学校全体の情報で、倍率・生徒数・めやすは学科ごとの情報だったため。

| 表                                          | 1行の単位                                     | 主な列                                                                                                                                               |
| ------------------------------------------- | --------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `high_school_campuses`（新）                | 1校                                           | 都県、学校名、都教委の学校番号、文科省の学校コード（13桁）、公式URL                                                                                  |
| `high_schools`（既存）                      | 学校×学科                                     | `campus_id` を足す                                                                                                                                   |
| `high_school_stats`（新）                   | 学校（か学科）×年度×項目×（学年・男女・内訳） | 項目キー、値（数値/文字）、延べ／現役／実進学、出典。★制服・校則の要約・指定も文字の値としてここに持つ（出典と確認日を他の値と同じ形で持たせるため） |
| `high_school_clubs`（新）                   | 学校×部                                       | 統一した部名、学校での呼び名、運動部・文化部・同好会の別、男女の別、週の日数、土日、段階、段階の根拠、出典                                           |
| `high_school_club_results`（新）            | 部×大会                                       | 年度、大会名、大会の格（全国/関東/都県/地区）、結果、出典。★**生徒名は入れない**                                                                     |
| `high_school_designated_universities`（新） | 学校×年度×大学                                | 出どころ（学校の公式／塾内で聞いた）                                                                                                                 |
| `high_school_events`（新）                  | 学校×出来事                                   | 種類（改築/制服/学級増減/学科改編/指定/施設）、時期、要約、出典                                                                                      |
| `high_school_notes`（後）                   | 学校×投稿                                     | 書いた人、教室、日付。入力画面のモックを出してから作る                                                                                               |

- **項目キーはコードで閉じる**（`region.ts` と同じ考え方）。自由記述にすると、表記の揺れで集計から黙って漏れる。
- **年度は「何の年度か」を列の意味で固定する。** 入試は入学年度、進学実績は卒業年度、生徒数は5月1日の年度。
  ★学校の経営計画は「R6実績」の付け方が入試年度と1年ずれることがある（日野で確認）。
- 権限は今の高校マスタと同じ。読みは認証済み全員、書きは admin / owner だけ。
  既定で anon / authenticated に付く ALL を revoke してから付け直す。
- 塾内の声（`high_school_notes`）だけは教室で書くので、権限を別に考える。

実装（第1段）:

- 表: `supabase/migrations/20260923150000_high_school_profiles.sql`。既存の学科の行から学校（301校）を起こし、
  ★学科の行を足したら親の学校を自動で付けるトリガーを置いた（既存の取込スクリプトは campus_id を知らないため）。
- 項目キー: `src/lib/highSchools/metrics.ts`。部名の統一: `src/lib/highSchools/clubKeys.ts`。
  資料の学校名・学科名 → マスタ: `src/lib/highSchools/importRules.ts`（いずれも .mjs から直接 import する）。
- 取込: `scripts/import-high-school-facts.mjs`。資料ごとの罠は [data/README.md](./data/README.md) の後半。
- 2026-09-23 本番に適用し、一括資料5つを取込済み：`high_school_stats` 5,582行（すべて確認済み）、`high_school_clubs` 52部（Premiere Club）、
  神奈川133校に文科省の学校コード。★Premiere Club には Tier1（11部）・Tier3（33部）のほかに **Tier2（10部）** もあった。

## 5. 出典と確認の決まり

1. **どの値にも「出典URL・資料の時点・確認日」を付ける。** 今のめやすの `verified_at` と同じ。
2. **AIヘルプには、人が確かめた値だけを渡す。** 面談の画面では、未確認の値を「未確認」と分かる形で出してよい。
3. **資料どうしで数を突き合わせる。** 合格実績表から数えた現役合格数が学校経営報告の数と一致する、
   都教委の倍率と経営報告の倍率が一致する、という確かめ方で、人が紙を見る手間を減らす。
4. **食い違いは両方残す。** どちらかに寄せない（例：松が谷の経営報告は「学級増」、都教委の発表は2025年度に普通科7→6学級の「学級減」）。
5. 民間のまとめサイト（みんなの高校情報等）からは値を取らない。古い（松が谷の男女数は合計が在籍数と合わなかった）うえ、利用規約の問題がある。
   例外は野球の一球速報（§1-7）。

## 6. 集める順番

1. **全校分が1つの資料にまとまっているものを一括で入れる**（スクリプト）
   - 都教委「都立学校における部活動の特別強化プロジェクト」Premiere Club 一覧（Tier1 11部・Tier2 10部・Tier3 33部）
   - 都教委「公立学校一覧」高等学校（学校別）Excel（学科×学年の生徒数・学級数）
   - 都教委「入学者選抜受検状況」PDF（★文字層に校名が無い。画像で読む）
   - 都教委「第一学年生徒の募集人員等について」（学級の増減）
2. **学校ごとに集めるもの**：学校経営報告・計画、合格実績PDF、部活動ページと部ごとのブログ、パンフ、生徒心得、一球速報。
   AIが出典つきの下書きを `docs/data/` に置き、人が確かめてから取り込む。
3. **神奈川**：県の生徒数Excel（男女別つき）と共通選抜の合格状況Excelを一括で入れ、あとは東京と同じく学校ごと。§8

手間の目安：日野1校で調査エージェントに約17分。85校を回すときは、並行で走らせる仕組みを別途相談する。

## 7. 試し調査で分かった罠（都立2校・2026-09-23）

- 学校サイトのPDFも都教委のPDFも、**文字層が壊れていて画像で読むしかない**ものが多い。
- 公開の有無は学校ごとにバラバラ（男女数：松が谷○・日野×。指定校一覧：日野○・松が谷×）。
- **調査エージェントは誤る。訂正も誤る。** 「アーチェリー女子の都総体2位は公式記録で確認できない」という訂正が誤りで
  （高体連の成績一覧に載っている）、和太鼓の「最優秀賞」は原文が「優秀賞」だった。
- 高体連の総合体育大会の成績一覧は4位まで。都立の強さを測るには浅すぎる。競技ごとの結果が要る。
- 回戦の呼び方が資料で違う（学校「1回戦」＝一球速報「2回戦」）。「初戦敗退」のように持つ。
- 学校サイトの本文は古いことがある（特色ページ「普通科6クラス」に対し、実際は6/7/7）。統計を優先する。
- 合格実績は延べ人数。表の見出しに誤植があった（R5の列が「R6」）。

## 8. 神奈川（希望ケ丘で試し調査・2026-09-23）

東京と同じ手順はおおむね通る。県全体の一括資料は次のとおり。

| 資料                                                                                                | 有無 | 中身・注意                                                                                                            |

| 県「公立高等学校 生徒数・学級数（学校別）」Excel（`/documents/122202/high_student-class_r07.xlsx`） | ○    | 学年別の生徒数・学級数に加え、★**全校の男女別人数が載っている**（東京の都教委資料には無い）。全日制と定時制は別シート |
| 県「共通選抜 学校別合格状況」（`/documents/132525/bessi4.xlsx`）                                    | ○    | 募集・受検・取消・合格・競争率・欠員。学科の種類ごとに別シートなので、1校の数字を拾うのに複数シートをまたぐ           |
| 県「公立高等学校 生徒募集定員」PDF                                                                  | △    | ★**全日制のページには学級数の列が無く、人数だけ。** 学級の増減は、定員の前年比と生徒数Excelの学級数から出す           |

確かめた値：生徒数1,060（男542・女518、27学級）、令和8年度の共通選抜の競争率1.42倍（Excelの行と一致）。

東京との違い：

- ★**県の統計に文科省の学校コード（13桁、例：希望ケ丘 `D114210010188`）が入っている。**
  今の神奈川のマスタは、県CSVのIDが重複していたので学校名で突き合わせている（`school_code` は NULL）。
  このコードを突き合わせのキーにできるかを、取込のときに確かめる。
- 学校評価報告書は県の様式が**文章だけで、満足度の数値が無い**。満足度の項目は神奈川では空になる。
- 学校によっては**制服が無い**（希望ケ丘）。項目として「制服なし」を持つ。
- 校則がかなり緩い学校がある（希望ケ丘の生徒心得には頭髪・服装・アルバイトの規定が無い）。
  「規定が無い」ことも校則の要約として持つ。
- 進学実績を**実進学者数と方式別の割合**で出す学校がある（希望ケ丘：一般63.5%・指定校16.7%・公募3.0%・総合型2.7%）。
  延べの合格数と実進学者数を混ぜない（`high_school_stats` の「延べ／現役／実進学」の区別に入れる）。
- 野球は「予選全勝1位」と「本大会ベスト32」のように段階の違う結果が並ぶ。本大会の結果で判定する。

5校とも本番に取込済み（未確認）。Opus の見直しで直したこと：

- **日野の指定校を44校→17校に直した。** 「一般選抜・総合型・公募による合格大学」の一覧（国公立を含む）を指定校として混ぜていた。
  パンフp.7の「主な指定校推薦」だけが指定校。手引き §6-2 に書いた。
- **部活の段階がぶれた。** 都立・公立だけの大会の成績で段階1、1回だけの県の賞で段階1、年度不明の実績で段階2、などが出た。
  手引き §6 に決まりを足し、5校の該当9部を直した。
- **延べか現役か書かれていない数に basis を推測で付けた**（清瀬の国公立14名）→ 入れずに未解決へ。
- 合格の数そのもの（日野のGMARCH 延べ7・日東駒専77・合計447など）は原本と一致した。

取込側で直したこと：

- 月までの日付（`2026-09`）が多い → `as_of` は月初にそろえ、`happened_on` は空にする。
- `basis` に空文字が混ざる → NULL にする（DBの CHECK は空文字を弾く）。
