# 進行表の目標に「終了」を入れる

作成日: 2026-09-07

## 1. 解きたい問題

講習で立てた目標が、講習が終わっても消えない。

いま目標カードに出ている「終了」バッジは**状態ではなく、試験日を過ぎたことを日付から毎回計算した表示**でしかない。
後続の目標を立てない限り消えず、`activeExamOf()` はその目標を選び続ける。

先に目標を「生徒×科目」に持ち替えた（`docs/progress-goal-subject-level-plan.md`）ため、影響が広がっている。
夏期講習で英語に立てた目標は、その生徒の**英語のテキスト全部**のカードに出続ける。

「次の目標へ」は次の目標を作る導線なので、次が無い場合の出口が無い。そこが穴。

## 2. 決定事項（2026-09-07）

| 論点 | 決定 |
| --- | --- |
| 誰が終われるか | **教室長以上のみ**。判定は既存の季節ラベルと同じ `role !== 'teacher'` |
| 終えたあとの挙動 | **A案**。目標が無い状態に戻る（＝講師はその科目の授業を記録できなくなる） |
| 終えたあとの文言 | **B案**。「目標が設定されていません」と煽らず、終えた事実を静かに書く |
| データ | 消さない。終了日時を持たせて履歴に残し、取り消せるようにする |

### 挙動と文言をあえて組み合わせている点

A案の挙動は「目標を立てるまで講師は記録できない」。B案の文言は落ち着いた書き方で、
記録できない理由に触れていない。そのままだと講師が「なぜ記録ボタンが押せないのか」を知る手段が無くなる。

そこで **B案の文言を主にしつつ、講師にだけ理由の1行を添える**（§4-2）。
教室長は目標が無くても記録できる（既存の `disabled` 条件が `role === 'teacher'` 限定）ので、
教室長には出さない。

## 3. DB変更

```sql
alter table public.student_textbook_exams
  add column if not exists closed_at timestamptz,
  add column if not exists closed_by uuid references public.user_profiles(id) on delete set null;

comment on column public.student_textbook_exams.closed_at is
  '目標を終えた日時。NULL=進行中。講習の目標が次の目標を立てるまで居座るのを止めるために教室長以上が付ける。行は消さない（履歴と取り消しのため）';
```

- `closed_by` の FK は **ON DELETE SET NULL**。講師アカウントを消したときに目標まで
  道連れで消えてはいけない（同じ罠を提案書FKと目標FKで2回踏んでいる）。
- インデックスは足さない。1生徒あたり数十行で、既存の
  `idx_student_textbook_exams_student_subject` で足りる。
- RLS は変更不要。行の所属（`student_id`）は変わらない。

## 4. コード変更

### 4-1. 目標の選択から外す

`newProgress.shared.ts` の `activeExamOf()` で `closed_at != null` を除外する。
除外は**日付での絞り込みより先**に行う。終了した目標は未来日でも選ばない。

`getExamsBySubject()` / `getSubjectExams()` は終了済みも返し続ける（履歴表示と取り消しに要る）。
除外するのは表示側だけ。

### 4-2. 目標カード（`TableView.tsx`）

**終了ボタン**: 目標カードの操作列、「次の目標へ」「編集」の並びに追加する。`role !== 'teacher'` のときだけ出す。
文言は「目標を終える」。押すと確認ダイアログを出す（誤操作すると科目全体の目標が消えるため）。

**終えたあとのカード**: いま `activeExam` が null のときに出している警告カードを、2つに出し分ける。

- **終了した目標がある場合**（B案の文言）
  - 見出し「目標なし」
  - 補足「{試験名}は {M/D} に終了しました」
  - ボタン「目標を設定する」
  - 講師のときだけ追加で1行「目標を設定すると授業の記録ができます」（§2 の理由）
  - 教室長以上には「終了を取り消す」を出す。**終了を取り消せる場所はここしか無い**
    （終了した目標はカードから消えるため）
  - 見た目は警告色ではなく通常のカード（`bg-white` + `border-[#e5e7eb]`）に寄せる
- **一度も目標が無い場合**
  - 現行の警告カード（「目標が設定されていません」）のまま。変更しない

「終了した目標」は、その科目の終了済みのうち `closed_at` が最も新しいものを指す。

### 4-3. API（`src/lib/api/progress.ts`）

```ts
closeStudentTextbookExam(id: string, closedBy: string | null): Promise<StudentTextbookExam>
reopenStudentTextbookExam(id: string): Promise<StudentTextbookExam>
```

`closedBy` は `useAuth()` の `profile?.id`。取れなければ null で通す（監査情報が欠けるだけで機能は動く）。

### 4-4. アラート（`src/lib/api/alerts.ts`）

`buildExamOverdueCandidates()` で終了済みを対象外にする。
**`latestExamDate` の計算からも外すこと。** 外し忘れると、終了した未来日の目標が「最新」になって
その手前の生きている目標が判定から落ち、目標未設定を検知できなくなる。

### 4-5. 型（`src/types/database.ts`）

`StudentTextbookExam` の Row / Insert / Update に `closed_at`・`closed_by` を追加。どちらも null 許容。

### 4-6. ヘルプFAQ（`src/lib/help/faqData.ts`）

同じPRで直す。書き方は `docs/help-authoring-guide.md` に従う。

- 「テスト目標の設定」（578行目付近）に、目標の終え方と「教室長以上だけができる」ことを足す
- 「試験が終わったら次の目標はどう設定しますか？」（2834行目付近）に、
  次の目標を立てない場合は「目標を終える」で閉じる、を足す
- 目標を終えると講師はその科目の授業を記録できなくなる点を明記する。
  **ここを書き漏らすと、記録できない講師にAIヘルプが答えられない**

## 5. 検証

### 自動テスト

- `activeExamOf()` が終了済みを選ばないこと（未来日の終了済みがあっても、生きている過去日を選ぶ）
- 終了済みしか無ければ null を返すこと
- `buildExamOverdueCandidates()` が終了済みでアラートを出さないこと
- 終了済みの未来日があっても、生きている過去日の目標のアラートが出ること（§4-4 の罠）

### 画面

同一科目に2冊以上テキストがある生徒で見る。

1. 教室長で「目標を終える」を押すと、**同じ科目の全テキスト**のカードから目標が消える
2. 消えたあとのカードに終えた試験名と日付が出る
3. 「終了を取り消す」で元に戻る
4. 講師でログインすると「目標を終える」「終了を取り消す」が出ない
5. 講師は目標が無い状態で「授業を記録」が押せない。理由の1行が出ている
6. 目標未設定アラートが、終了した目標では鳴らない
