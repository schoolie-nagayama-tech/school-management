## 0. 何をするか

模試の個人帳票（進研テスト・Vもぎ）と PCS の結果帳票を PDF で入れると、
**講習提案書（`seasonal_proposals`）の単元とコマの下書き**が、いつもの提案書の編集画面の形で入る。
教室長はそれを手で直して保存する。

- 教室長が毎回手で組んでいる「なぜこの単元を何コマか」を、成績表の事実から組む。
- **組むのは規則（システム）。AIは PDF を書き写すだけ。** 数字の判断（コマ数・難問の採否・教材の組み合わせ）を AI に任せない。
  組むたびに結果が変わらないこと、画面で理由を説明できることを優先する（[AIは書かせず整える] の方針）。
- 下書きは下書き。**最後に決めるのは教室長**（難問を2コマにするか、など）。

## 2. 実物で確かめたこと（読み取り精度）

実物3人分で試した（生徒名は伏せる。PDF・画像はリポジトリに入れていない）。

**PCS（結果帳票・数学/英語）**
- PDF の文字の層に **●△× の印が座標つきで入っている**。数学は単元名も文字なので、
  「⇒ の右にある印＝今回」で読める。今回の印23件すべて画像と一致。**AI不要**。
- 英語は単元名が図形化されていて文字が無い（印と％だけが文字）。
  ただ様式は全員同じなので、**様式ごとに「座標 → 単元」の表を1回作れば機械的に読める**。
- 印は ●（できる）△ × の3つ。**空欄＝出題なし**。群の「－－」は **×が付いていて0%**（出題なしではない）。
- 左の枠＝前回、右の枠＝今回。赤の印が今回のテスト。

**進研テスト・Vもぎ（個人帳票）**
- 全ページ画像。AIで読む。2ページ目の **学力分析表** が本体：領域ごとに、設問番号・内容・全体の正答率・本人の正誤。
- 正誤は ○ ／ × ／ **×→◎**（実力なら取れた。帳票自身が「復習の優先度が高い」と書く）／ **×→★**（もう一歩）。
- ★**検算できる**：領域の本人の得点率は「○の数 ÷ 設問数」と一致する（進研テスト 10領域・Vもぎ 7領域、全部一致）。
  1問でも読み違えると合わなくなるので、**システムが機械的に読み違いを見つけられる**。
- ★**部分点の設問**（作図・証明・英作文）は、正答率の欄が平均点、正誤の欄が本人の得点。得点率で検算できない。
- Vもぎの1ページ目に **第1志望校の合格基準偏差値** と **教科ごとの偏差値** がある（§5.3 で使う）。
- 3・4ページ目（答案の画像）は使わない。

**Vもぎの英語は技能別**（文脈把握・理由把握・適語補充・英問英答・内容一致・自由英作文）で、文法の単元に当たらない。
技能別の単元を持つ教材（フォレスタゴール・必勝シリーズ）になら当てはまる。技能名は回をまたいで同じ。
数学は設問の内容名が回ごとに変わる（「平行四辺形の面積」など）が、都立の大問構成は決まっている。

## 4. 読み取り

### 4.1 PCS：ブラウザの中で読む（PDFを外に出さない）

- `pdfjs-dist` をブラウザで動かし、文字と座標を取る。**PDF はサーバーにも Anthropic にも送らない**。
- 読み取り部品は純関数にして、座標の並びを受けて `{ 単元名, 前回の印, 今回の印 }[]` を返す（テスト可能にする）。
  - 数学：`⇒` と同じ高さ（±7pt）で左にある文字を単元名、`⇒` の右 25pt 以内の印を今回。
  - 英語：様式の座標表（`src/lib/scoreSheet/pcsLayouts.ts`）で、印の座標から単元を引く。
- ★サーバー（Vercel）で pdfjs を動かさない。ESM の require で本番全ページ500 を出した前例がある
  （落とし穴メモ「本番全ページ500=サーバーのjsdom」）。
- 種類の判定：文字の層に「Pcs」「結果帳票」と「中学数学」「中学英語」があるか。無ければ模試として §4.2 へ。

### 4.2 模試：サーバーで AI に書き写させる

- 経路：`POST /api/ai/score-sheet/read`（教室長以上・`getApiAuth`）。PDF は **1・2ページ目だけ** を切り出して送る
  （`pdf-lib`。答案の画像は送らない＝送る量と中身を減らす）。
- モデル：`CLAUDE_MODELS.best`（決定2）。PDF を document として渡し、**決まった形の JSON だけ**を返させる。
- AI への約束（プロンプトに固定）：
  - **書き写すだけ**。まとめない、推測しない、足さない。読めない欄は `null`。
  - 正誤は帳票の記号のまま（`o` / `x` / `x_to_double` / `x_to_star`）。部分点は数字。
- 返す形（概略）：
  ```ts
  {
    doc_type: 'shinken_test' | 'vmogi_tokyo',
    exam: { label: string; date: string | null; grade: number },
    ss: { [subject]: number | null },            // 教科ごとの偏差値（1ページ目）
    first_choice: { name: string; base_ss: number | null } | null,  // Vもぎのみ
    subjects: [{
      subject: 'math' | 'eng' | ...,
      areas: [{
        name: string; own_pct: number | null;    // 領域の本人得点率。部分点の領域は null
        items: [{ q: string; content: string; rate: number | null; avg: number | null;
                  result: 'o' | 'x' | 'x_to_double' | 'x_to_star' | number }]
      }]
    }]
  }
  ```
- **検算（システム）**：領域ごとに `round(○の数 ÷ 設問数 × 100)` と `own_pct` を比べる。
  - 一致 → そのまま使う。
  - 不一致 → その領域を「要確認」にし、**人が○×を直すまで下書きに使わない**（画面で設問ごとに直せる）。
  - 部分点の領域 → 「検算の対象外」と表示。本人の得点 < 平均点 を×として扱う。
- 名前の取り違え防止：帳票の氏名・学年と、選んでいる生徒が違えば止める（氏名は照合にだけ使い、保存しない）。

### 4.3 AI 機能の栓

- `src/lib/ai/features.ts` に新しいキー（例 `score_sheet_read`）を足す。**成績表の読み取りは既存の栓と混ぜない**
  （plan_theme を開けた教室から、帳票の画像まで流れ出さないように）。
- 外に出るもの（`AI_FEATURE_SENDS`）：「模試の個人帳票の1・2ページ目（氏名・学校名・成績・志望校を含む）」。
- `AI_FEATURE_MIN_ROLE` は `manager`。入口のボタンも同じ境界で隠す（動かないものは出さない）。
- PCS の読み取りは AI を使わないので、栓が閉じていても使える。

## 5. 下書きの規則（`src/lib/scoreSheet/planRules.ts`・純関数・テスト必須）

### 5.1 根拠（事実）を集める

| 出どころ | 根拠になるもの | 根拠にしないもの |
|---|---|---|
| PCS | 今回の印が △・× の単元 | ●・空欄（出題なし） |
| 模試 | ×・×→◎・×→★、部分点で平均点未満 | ○ |

- **難問**：全体正答率が20%未満の×。**その教科の偏差値が55以上なら根拠に入れ、未満なら外す**（外したものは画面に一覧で出す）。
- **食い違い**：PCSでは●なのに模試では×の単元には注記を付ける。どちらを採るかは教室長が決める。
- 模試の設問1問は、単元1か所だけに当てる（二重に数えない）。

### 5.2 中1・中2（教材の単元に当てる）

対応表（§6.2）で根拠を教材の単元に落としたあと、教科ごとに組む。

**数学（軽く）**
1. **計算の範囲**（教材ごとに設定。フォレスタステップ2年なら1〜4章と「等式の変形」）は、
   章の中で**隣り合う**弱点の単元を束ねて1つにし、コマは `ceil(単元数 ÷ 3)`。
2. それ以外は1単元1コマ。隣り合う単元で根拠（出どころ）が同じなら束ねて1コマ。
3. **メリハリ**：計算以外で、PCSの×と模試の×が**両方**ある単元は2コマ（束ねない）。

**英語（重く）**
1. 1単元1コマ。根拠が2つ以上なら2コマ。
2. 章のまとまり（「〜章のまとめ」で区切る）の中で、**弱い単元にはさまれた単元**を「定着」として1コマ足す。
3. 弱い単元が2つ以上ある章は、その **「〜章のまとめ」** も「定着」として1コマ足す。

**目的タグ**（既存の `intent_tag`）：PCSで× → 苦手克服／△だけ・模試だけ → 苦手補強／前後に足した単元 → 定着。

**束ね方の制約**：いまの提案書の結合（`groupSelectedUnits`）と同じく、**隣り合う単元だけ**を束ね、
束ねた単元もそれぞれ `koma_count ≥ 1` を持ち、合計は先頭の単元だけで数える。これを破ると、保存したあと編集画面で壊れる。

実物での結果（生徒A・中2）：数学21コマ＋英語12コマ＝33コマ。

### 5.3 中3（都立対策コースに当てる）

1. **教材の組み合わせを決める**（決定11・16）：Vもぎの第1志望の合格基準偏差値が60以上 → **上位校**
   （ウイニングフィニッシュ・必勝シリーズ・都立入試過去問）。それ以外 → **中堅校**（フォレスタゴール・必勝シリーズ・都立入試過去問）。
   組み合わせは、講習一覧の都立対策コース（冬期・中3）の単元とまとまりを借りる（§6.3）。
2. **当ててよいのは、そのコースに入っている単元だけ**。コースに無い単元には当てない。
3. ×が当たった単元を、**コースのまとまり（`group_number`）ごと**入れる。コマは**コースの値**（基本コマ）。
   同じまとまりに根拠が2つ以上あれば＋1。
4. **過去問は全員5年度分**（コースどおり）。弱点に関係なく入れる。目的タグは「直前演習」。
5. **難問は自動で2コマにしない**。「難問を含む。2コマにするかは教室長が判断」の札を出す。
6. 当てる×が1つも無い冊は入れない（0コマの提案書を作らない）。画面に「入れていない冊」として出す。
7. 目的タグ：難問だけが根拠のまとまり → 応用発展、それ以外 → 苦手補強。

実物での結果（生徒B・中3・中堅校）：数学9コマ（うち過去問5）＋英語17コマ（うち過去問5）。
上位校に切り替えると数学12・英語15。数学の偏差値が55未満なら、難問3問が外れて数学7。

### 5.4 定数（1か所に置く）

```ts
export const HARD_RATE = 20;      // 全体正答率がこれ未満の×は難問
export const HARD_SS = 55;        // 教科の偏差値がこれ以上なら難問も入れる
export const UPPER_BASE_SS = 60;  // 第1志望の基準偏差値がこれ以上で上位校の組み合わせ
export const CALC_PER_KOMA = 3;   // 計算の範囲は3単元で1コマ

```

### 6.2 対応表

**第1段はテーブルを作らない。**

  送るのは設問の番号・内容名と単元名だけ（個人の情報を含まない）。返ってきた単元IDが一覧に無ければ捨てる。
  画面の当てはめ表で教室長が選び直せる。

### 6.3 中3の組み合わせ：講習一覧のコースを指す

- 中堅校・上位校の組み合わせは、**講習一覧（`seasonal_courses`）の都立対策コース**を指して持つ。
  コース名の文字列で探さない（名前は教室が変えられる）。
- 第1段：その教室の講習一覧（冬期・中3・有効）から、名前に「都立入試対策」「数学/英語」「中堅校/上位校」を含むコースを**初期値として選び**、
  画面で選び直せるようにする（名前が変わっていても教室長が選べば動く）。テーブル（`score_plan_course_sets`）は第2段。
- ★講習一覧のコースのまとまりには、間に対象外の単元をはさむもの（例：ゴール英語の 2-3・4-1・4-2）がある。
  提案書の結合は隣り合う単元だけなので、**取り込むときに隣り合う範囲で切り直す**。

### 6.4 提案書への保存（既存テーブル）

- 冊ごとに `seasonal_proposals` を1件（生徒×テキスト×期）。状態は **下書き**。
  いまの複数冊作成（`proposalMultiBook.ts`）と同じ保存の仕方を使う。
- 単元は `seasonal_proposal_units`（`koma_count` / `group_id` / `intent_tag`）。
- **根拠は `seasonal_proposal_units.reason` に短い文字列で入れる**（例「PCS 比例の式 ×／進研 3(1) ×」）。
  この列は編集画面が保存・復元しているのに画面にも印刷にも出ていない死に列で、**保護者には出ない**。
  あとからコンセプトAI（テーマをふくらませる）の材料にもできる。
- 同じ期にもう提案書がある冊は、いまの新規作成と同じく「その提案書に単元を足す」になる（上書きしない）。

## 7. 画面

モック第4版のとおり。**提案書の作成画面と同じ部品**で組む（決定7）。

- 入口：新規作成の最初の画面（`CreateMethodScreen`）に3つ目「**成績表から作る**」を足す。
- 新しいページ（案 `/proposals/new/from-scores`）を、既存の部品で組む：
  `ProposalBookTabs` ／ `UnitList`・`UnitRow` ／ `EditorBottomBar` ／ `SelectionPill`。
  ★`ProposalEditor.tsx`（2,171行）は改造しない。複数教科を持たせると壊しやすいので、部品を借りて別ページにする。
- 足すのは次だけ：
  1. **成績表の欄**：入れたPDFの一覧。押すと読み取った中身（PCSの印、模試の検算表と×の設問）。検算が合わない領域はここで○×を直す。
  2. **上の帯**：理由を出す。中2は合計と目安、中3は「第1志望の基準偏差値 → 使う教材」「教科の偏差値 → 難問を入れるか」。
     中3は「教材の組み合わせを変える」で中堅校⇄上位校を切り替えられる。
  3. **教科の切り替え**：1画面の冊は3冊まで（`MAX_TEXTBOOKS`）なので、教科を切り替えてその教科の冊をタブに出す。
  4. **単元行の下の根拠の札**：PCS・進研・Vもぎのどの問題か、食い違い、基本コマ＋加算、難問の札。
  5. 中1・中2は、冊ごとに **テキストの差し替え**と対応表の状態（確認済み／AIの候補／まだ無い）。
- 操作はいまの編集画面と同じ（行を押して＋1、±、グループ化、目的タグ、テキストを追加）。
- 保存ボタンは「保存（提案書N件）」。

## 8. 権限・個人情報

- 使えるのは **教室長以上**（入口もAPIも同じ境界）。
- 外に出るのは模試の帳票の1・2ページ目だけ（Anthropic）。PCS は外に出ない。
- PDF も読み取り結果も保存しない（決定15）。残るのは提案書と根拠の文字列だけ。
- リポジトリは公開：**テストの固定データに実物の数字をそのまま使わない**（値を変えた作り物にする）。生徒名・学校名を書かない。
- 規約・プライバシーポリシー：直さない（決定14。AIへの送信は氏名を含めて第5条の2で説明済み）。
