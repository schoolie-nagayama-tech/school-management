# 問合せ管理機能 要件定義（ベータ版）

作成日: 2026-06-10
改訂履歴:
- v2 (2026-06-10): GASコード・ヤマトB2テンプレート提供を受けて確定化
- v3 (2026-06-11): HPシステムのCSVエクスポート（boshu_applicant_*.csv）を確認し**CSV取込を主動線に変更**。ネコポス送り状種類をAに訂正・投函完了メール廃止（有料化のため）。メール送信は手動のみに変更（自動ステップ送信は廃止、送信候補の提示まで）。Webアプリならではの拡張提案を追加。

## 1. 背景と目的

現状、問合せは本部HP（FCの問合せ管理システム）で受け付けているが、HP側には集計・分析・リマインド機能がなく名簿としてしか機能していない。そのためスプレッドシート（問合せ管理表）+ GAS で運用しているが、転記の手間がある。本機能はこの運用を本アプリに移管し、転記の手間を最小化しつつ、分析・リマインド・追客・発送を一元化する。

### 現行データの実態（問合せ管理表 880件の分析結果）

| 項目 | 値 |
|---|---|
| 教室 | 永山 302 / 清瀬 269 / 京王堀之内 190 / 緑園都市 119 |
| 問合媒体 | 本部HP 389 / 塾ナビ 263 / 看板・外パンフ 73 / 友人紹介 40 / 塾選 37 / 兄弟姉妹 21 / チラシ 21 / 塾シル 15 / Ameba塾探し 6 / 直来 1 |
| 申込内容 | 資料請求 411 / 無料体験授業 260 / 学習相談・教室見学 121 / その他 53 / 講習 1 |
| 結論 | 入会 362 / 連絡不通 312 / 没 98 / 体験没 79 / 対応中 29 |

→ 全体入会率 41%。連絡不通が 35% を占めており、追客（リマインド・メール）の改善余地が最も大きい。

### HPシステムのCSVエクスポート（確認済み・取込の正）

`boshu_applicant_<教室CD>.csv`（Shift_JIS / 57列 / 教室単位でエクスポート）。**問合せNO（一意ID）を含む**ため、再取込時の重複防止・差分更新が可能。コピペ+パースより正確に全項目が取れるため、これを取込の主動線とする。

主な列: 問合せNO / 受付日時 / 教室CD / 教室名 / 開封状況・開封日 / ステータス / 問合せ経路 / 受付タイプ / 問合せ内容 / 保護者氏名（漢字・カナ）/ 生徒との関係性 / 生徒氏名（漢字・カナ）/ 電話番号（**先頭0付きで入っている**）/ メールアドレス / 性別 / 学年 / 学校名 / 郵便番号・都道府県・ご住所・建物名 / ご質問・ご要望 / 通塾目的 / 希望科目 / 通塾経験 / 認知動機（**カンマ区切り複数値あり**）/ 問合せ動機 / 資料送付日 / メモ / 面談日時・担当者・メモ / 体験日時・担当講師・メモ / 再面談 / 返答 / 結果 / 入会成約日 / 個別週回数 / デバイス / 最終更新日

## 2. スコープ

### ベータ版（今回）

- 入り口: 設定ページ（`/settings`）に `requiresAdmin` のカードとして追加（ダッシュボード機能と同じ方式）。ナビゲーションには出さない。
- 対象ロール: admin / owner のみ（ベータ期間中）。
- 機能: 問合せ台帳 / CSV取込（HPエクスポート）/ 既存スプレッドシートの一括移行 / 分析 / リマインド / メール送信（Resend・手動・テンプレ編集UI）/ ネコポス B2取込CSV出力 / Slack通知

### スコープ外（確定）

- クーリングオフ日の管理 → やらない
- 個人情報の保持ポリシー（匿名化バッチ等） → やらない
- メールの自動送信（ステップメールの送信は人の1クリックを必須とする）
- 電話番号の先頭0付与などExcel都合の変換 → 不要（CSVに完全な番号が入っており、DBはtext型でそのまま保持）
- manager への開放、ヘルプFAQへの掲載（GA時に実施）

## 5. 機能要件

### F-1. 問合せ台帳（一覧・詳細）

- 一覧: 教室・期間・ステータス・媒体・学年でフィルタ。デフォルトは「対応中」を上に。
- 詳細: 基本情報、コンタクト履歴のタイムライン（追加フォーム付き）、メール送信記録、HP原文（raw_source）の参照。
- ステータス変更時に必要日付の入力を促す（入会→入会日・週回数、体験没→体験日 など）。
- 入会確定時: 「生徒として登録」ボタンで students へワンクリック変換（氏名・カナ・学年・連絡先をプリフィル）し `linked_student_id` を設定。既存生徒への紐付けも可。

### F-2. CSV取込（主動線・転記レス化）

HPシステムの問合せCSVエクスポート（`boshu_applicant_*.csv`）をアップロードして取込・同期する。

- **文字コード**: Shift_JIS（cp932）を自動判定してデコード。
- **upsert**: `問合せNO` をキーに、新規は作成・既存はスキップ。既存でHP側に更新がある行（最終更新日が前回取込より新しい）は差分を一覧表示し、選択して反映（アプリ側で編集済みのステータス・日付は上書きしない。raw_source は常に最新化）。
- **教室マッピング**: 教室CD（5M13等）→ inquiry_school_settings.hp_school_code で school_id を解決。未登録CDはエラー表示。
- **値の正規化**:

| 項目 | 変換ルール |
|---|---|
| 学年 | `中学２年`→`中2`、`高校３年`→`高3`、`小学５年`→`小5`（全角→半角含む） |
| 性別 | 男性→男 / 女性→女 / 空→不明 |
| 電話番号 | **変換なし**（先頭0付きで入っている。Excel都合の0付与ハックは廃止） |
| 申込内容 | 受付タイプ: 体験授業→無料体験授業 / 資料請求・学習相談・教室見学はそのまま / 料金・講習・キャンペーン→その他 |
| 問合手段 | 問合せ経路: HP・CC→本部HP / 塾ナビ→塾ナビ / 教室電話→電話 / 直接来校→直来 / その他外部サイト→メモ欄の「塾選」「塾シル」で判定 |
| 問合媒体 | 認知動機（**カンマ区切り複数値**）に優先順位を適用: 友人・知人の紹介 > 教室の看板(→看板・外パンフ) > チラシ > 塾比較サイト・クチコミサイト(→問合手段の値を流用) > ホームページ(→本部HP)。判定不能は空にして取込後に手動設定 |
| ステータス | 結果列: 入会→enrolled / 空→in_progress。HP側の面談日時・体験日時・入会成約日・資料送付日・個別週回数も対応カラムへ |

- 取込結果サマリ（新規N件 / 更新候補N件 / スキップN件 / エラーN件）を表示。
- **手入力フォーム**も用意（電話・直来などHPに載らない問合せ用。hp_inquiry_no = null）。
- 貼り付け取込（HP詳細ページのコピペパース）は補助動線としてGAで検討（CSVで運用が回るかをベータで検証してから）。

### F-3. 一括移行取込（初回のみ）

- 既存スプレッドシート「問合せ管理」（880件）を .xlsx/CSV アップロードで移行。列マッピングは現行ヘッダ固定。1st/2nd/3rd の日付・反応は inquiry_contacts、メール・SMS送信日は inquiry_mail_logs に展開。
- 移行後にHPのCSVを取り込むと電話番号・メール一致で重複しうる → 移行時に hp_inquiry_no が無いため、CSV取込時に「電話番号+受付日時が近い既存レコード」を検出して紐付け（hp_inquiry_no を後付け）する突合処理を入れる。
- PostgRESTの1000行上限に注意し、取込・一覧・集計はページング必須。

### F-4. 分析・プロット

recharts（導入済み）で実装。教室・期間（問合年月ベース）で絞り込み。

1. **ファネル**: 問合せ → コンタクト成功 → 体験 → 入面 → 入会。段間の転換率と全体入会率。
2. **月次推移**: 問合せ件数・入会件数・入会率の折れ線/棒（教室別系列）。
3. **媒体別分析**: 媒体ごとの件数・入会率・連絡不通率。申込内容別のクロスも。
4. **リードタイム**: 問合せ→入会日数、体験→入会日数の分布（中央値・平均）。
5. **決着内訳**: 構成比（ドーナツ）。
6. 全教室俯瞰ダッシュボードへの指標連携はGA以降。

### F-5. リマインド

既存アラート基盤（`src/lib/api/alerts.ts` + `alert_settings`）と同じパターンで「問合せアラート」を追加。ベータでは問合せ一覧ページ上部に表示（GAで AlertBoard 統合）。

| アラート | 判定 |
|---|---|
| 初回コンタクト未実施 | 対応中 かつ コンタクト履歴0件 かつ 問合せから1日経過 |
| 対応遅延（GAS互換） | 対応中 or 連絡不通 かつ 体験日・入面日が空 で、経過日数が **3/5/7/10/14/21/30日**（教室別に変更可） |
| 追客メール送信候補 | trigger_days 到達済みで未送信のテンプレがある（→ F-6 の送信画面へ誘導） |
| 資料未発送 | 資料請求 かつ material_sent_at 空で N 日経過 |
| 体験後フォロー | trial_at 翌日以降に決着もコンタクトも無い |

### F-6. メール送信（手動・Resend・テンプレ編集UI）

送信基盤は **Resend**（`supabase/functions/send-form-notification` で導入済み、レート制限対応あり）を流用。**送信はすべて人の操作を起点とする（自動送信なし）**。

- **個別送信**: 問合せ詳細から テンプレ選択 → 差し込みプレビュー → 送信。
- **本日の送信候補**（現行GASの自動下書き相当）: 「対応中 or 連絡不通、体験日・入面日が空、問合日 + trigger_days ≦ 今日、未送信」の問合せ×テンプレを一覧表示 → 内容確認 → チェックして一括送信。送信ログで重複防止。
- **一括送信**（現行 `createEmails` 相当): 期間・学年・学校種別・結論・媒体・教室で絞り込み or 一覧でチェック → テンプレ適用 → 対象プレビュー → 一括送信。メールアドレス空・「なし」はスキップ。
- **テンプレ編集UI**: 変数チップ挿入・ライブプレビュー・テスト送信（F-記載）。
- **差出人**: 既存の検証済みドメインを共用し、問合せ用に専用アドレス（例: `info@<既存ドメイン>`）+ 教室別表示名（`スクールIE永山校`）を推奨。Reply-To は教室メール。ドメインを分けるとDNS設定とレピュテーション育成が二重になるため、同一ドメイン・アドレス分離が現実的。
- SMS用短文テンプレも管理（送信は手動コピー）。

### F-7. Slack通知（GAS移植）

Slack Incoming Webhook URL は `/settings/integrations`（admin専用・既存ページ）に保存。教室別メンションIDは inquiry_school_settings。スケジューラは pg_cron → Edge Function（通知のみ。メール送信はしない）。

| 通知 | タイミング | 内容 |
|---|---|---|
| 日次サマリー | 平日13時 | 教室別: 対応中 / 連絡不通 / 体験予定あり / 入面予定あり / 入会 / 体験没 の件数 |
| 週次レポート | 月曜13時 | 教室別: 新規問合せ / 体験実施 / 入会 / 体験没 / 入会率（直近7日） |
| 対応遅延アラート | 平日13時 | 該当案件を日数降順で列挙、教室担当者にメンション |
| 送信候補リマインド | 平日13時 | 本日の追客メール送信候補が N 件ある旨（送信はアプリ内で手動） |

### F-8. ネコポス伝票出力（ヤマトB2クラウド）

GAS `exportNekoPosCSV` の移植。B2クラウド「外部データ取り込み基本レイアウト」（95列）準拠。

- 一覧で発送対象（資料請求で未発送など）をチェック → 「ネコポスCSV出力」→ ダウンロード → B2クラウドに取込。
- 出力値:
  - **送り状種類 = `A`（ネコポス）** / 出荷予定日 = 当日 / 品名1 = `資料` / 発行枚数 = `1` / 個数口表示フラグ = `1`
  - お届け先: TEL・〒（ハイフン除去）・住所（都道府県+住所+建物名連結）・氏名。**保護者名が空またはカナのみの場合は生徒名を使用**（カタカナ判定 `/^[ァ-ヶー\s]+$/`）。
  - ご依頼主・請求先顧客コード・運賃管理番号: inquiry_school_settings から教室別に取得。
  - **投函完了メールは設定しない**（有料化のため廃止）。
- 出力と同時に material_sent_at を当日で記録（トグルで無効化可）。
- CSVの文字コードはB2クラウドの取込設定に合わせる（実装時確認。既定はShift_JISの想定）。

### F-9. 設定ページ入り口（ベータゲート）

- `/settings` の settingsGroups に「問合せ管理（ベータ）」を `requiresAdmin: true` で追加。
- `/admin/inquiries` 配下はサーバ側でも `requireAdmin`（`src/lib/api-auth.ts`）で防御。

## 6. Webアプリならではの拡張提案（Excelの枠の外）

Excelでは構造的に不可能だった機能。ベータ後の優先度判断用。

### 推奨度: 高

1. **自社問合せフォーム（転記の根本解消）**: 保護者ポータル（`/portal`）と同じ公開フォーム基盤で問合せ・体験申込フォームを自前運用。チラシ・看板・校舎前QRコードからの流入は最初からアプリに直接入る（転記ゼロ・媒体はQRパラメータで自動記録）。HP経由は残るが、自前経路の比率を上げるほど転記が減る。既存の公開フォーム+service roleパターン（portal/form-responses）がそのまま使える。
2. **メール開封・クリック計測**: Resend の Webhook で開封/リンククリックを inquiry_mail_logs に記録。「開封したが返信なし」を優先追客するなど、追客の優先順位付けが変わる。連絡不通35%への最も直接的な打ち手。
3. **体験予約のセルフスケジューリング**: 現在メールに TimeRex のURLを貼っている部分を内製化。教室の空き枠から保護者が予約 → trial_at 自動入力 + コンタクト記録。既存のスケジュール・座席表機能と連動でき、体験コマの仮割当て（講師アサイン）まで繋げられるのはこのアプリだけの強み。
4. **名寄せ・家族リンク**: 電話番号・メール・住所の一致で、過去問合せ／在籍生徒／退会生徒と自動リンク。「兄が在籍中」「2年前に没になった家庭の再問合せ」が詳細画面で見える。再問合せ・兄弟姉妹は成約率が高い重要セグメント。

### 推奨度: 中

5. **今日のアクションビュー（モバイル）**: 教室長がスマホで見る「今日の追客タスク」。`tel:` リンクでワンタップ発信 → その場で結果を記録。コンタクト記録の入力コストを最小化。
6. **商圏分析**: 郵便番号・学校名別の問合せ数・入会率。チラシ配布エリアや看板投資の判断材料。デバイス列（PC/SmartPhone）も流入分析に使える。
7. **失注理由の記録**: 没/体験没時に理由（料金/他塾/時期尚早）を選択式で記録 → 失注分析。
8. **入会オンボーディング連携**: 入会→生徒登録→初回フォーム案内→請求設定のチェックリスト化。問合せ管理と既存機能を繋ぐ動線。

### 推奨度: 低（様子見）

9. **目標管理**: 教室×月の問合せ・入会目標と達成率（全教室俯瞰ダッシュボードに統合する方が自然かも）。
10. **対応者別の成約分析**: inquiry_contacts.created_by ベース。講師アカウント化（7月予定）後に意味が出る。
