指導契約（1対1／1対2・45分／90分）を「正のソース」に戻す — モック v1

いまは授業を登録するとその比率が契約に書き戻されるため、取り違えても矛盾が残らない。
契約を動かせるのは「契約を変更する」操作だけにし、授業登録フォームからは書かない。

なぜ既存の授業を書き換えないか

保護者に見せているのは契約ではなく実登録（schedule_entries.ratio）です。 契約を直したついでに過去の登録まで書き換えると、実際には1対2で受けた授業が 画面上だけ1対1に見える。表示が誤りを覆い隠す装置になるので、契約の変更は 契約だけを動かす。
  • ポータル・座席表のバッジは実登録のまま（今回の変更対象外）。
  • 過去分の食い違いは消さずに見えるようにするのが§4のアラート。
  • 「これから作る授業」の既定が契約から引かれるので、放っておいても新しい登録は正しくなる。

履歴に残すもの

変更前後の（比率・時間）／理由／補足／変更した人／日時。 生徒詳細から誰でも読める（変更できるのは教室長以上）。

拾う条件

  • 比率の食い違い — schedule_entries.ratio ≠ 契約.ratio
  • 時間の食い違い — duration_minutes が契約と違う（45分契約が90分で入っている等）
  • 契約が無いのに授業がある — 講師が座席表から入れた分・移行漏れ
  • 1対1の隣に人がいる — 同じ講師×日付×コマに ratio=1 と他の生徒。 登録時は canPlaceEntry が弾くが、振替・臨時・契約変更の後追いでは弾けない

対象は今日以降の登録（過去は直せないので出さない）。 研修生徒 is_test・デモ教室 is_demo は除外。

欠席で相方が消えるのは食い違いではない（登録は1対2のまま）。出さない。

5. 移行 — 契約の一括確認（一度きりの棚卸し）

45分専用の科目レコードを廃止する

いま45分は2通りの持ち方が混在している。小学の「国語」「算数」「英語」は 45分版と90分版が別の科目レコードとして登録されており、 一方で永山校では10/1から「普通の科目＋パターン側で45分指定」へ切り替える版が既に入っている。 契約が duration_minutes を持つなら45分専用の科目は要らなくなるので、廃止して一本化する。

45分科目の参照先件数付け替え
通塾日程パターン16科目IDを90分版へ＋duration_minutes=45
授業コマ130同上
マッチング提案7科目IDを差し替え
指導可能科目（講師）22〜23名45分IDを外す（90分IDは既に入っている）
受講科目・契約・教材・講座・保留授業・テスト対策0影響なし
half_position は触らない（NULL＝全コマ扱いのまま）。 いまも45分の授業はコマを丸ごと使っているので、ここを同時に変えると席の詰まり方が変わってしまう。 前後半の割り当ては教室長が後から座席表で設定する。

このデータ移行は本丸とは別のマイグレーションに分ける（同じPRだが、単独で適用・巻き戻しできる形にする）。

6. データの持ち方

student_subject_contracts（列を足す）

  • duration_minutes smallint NULL（45 / 90。NULL＝科目マスタに従う＝いまと同じ意味）
    「この生徒のこの科目は45分」を契約で言えるようにする。 いまは教室共通の subjects.duration_minutes しか無い。
  • confirmed_at timestamptz NULL ＋ confirmed_by
    移行時に一括投入したものを「暫定」として区別する。NULL＝要確認。
  • updated_by uuid（最終変更者）

既存行は duration_minutes = NULL ＝ 挙動不変。

student_subject_contract_changes（新設）

  • school_id / student_id / subject_id
  • from_ratio, from_duration_minutes（初回登録は NULL）
  • to_ratio, to_duration_minutes
  • reason_code（訂正／コース変更／学年切替／その他）＋ reason_note
  • changed_by, changed_at

RLS は check_school_access(school_id)（既存の契約テーブルと同型）。 書き込みは教室長以上を API 側で確認。

7. 触らないところ

  • 保護者ポータルと座席表のバッジは実登録（schedule_entries.ratio）のまま。 契約側に切り替えない。食い違っているときに画面が「1対1」と出て保護者を安心させると、 表示が誤りを覆い隠す装置になる。
  • 席の占有モデル（seatOccupancy.ts）・登録時のブロックはそのまま。
  • 講習の申込フォーム（KoushuEnrollmentFormModal）は契約を既定値として読むだけで 書いていないので、そのまま。ただし読む先が（比率, 時間）の組になる。
