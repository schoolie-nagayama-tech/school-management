なぜ既存の授業を書き換えないか

保護者に見せているのはコースではなく実登録（schedule_entries.ratio）です。 コースを直したついでに過去の登録まで書き換えると、実際には1対2で受けた授業が 画面上だけ1対1に見える。表示が誤りを覆い隠す装置になる。
  • ポータル・座席表のバッジは実登録のまま（今回の変更対象外）。
  • 過去分の食い違いは消さずに見えるようにするのが§5。
  • これから作る授業はコースに従うので、放っておいても新しい登録は正しくなる。

直すのは登録のほうです。保護者に見えているのは実際の登録です。

拾う条件

  • 比率の食い違い — schedule_entries.ratio ≠ コースの比率
  • 時間の食い違い — 45分コースが90分で入っている等
  • コース未設定なのに授業がある — 講師が座席表から入れた分
  • 1対1の隣に人がいる — 同じ講師×日付×コマに ratio=1 と他の生徒。 登録時は canPlaceEntry が弾くが、振替・臨時・コース変更の後追いでは弾けない

対象は今日以降の登録（過去は直せないので出さない）。 研修生徒 is_test・デモ教室 is_demo は除外。

欠席で相方が消えるのは食い違いではない（登録は1対2のまま）。出さない。
座席表の稼働直後は「コース未設定」が大量に出る可能性がある。 未設定は種別を分けて件数だけ畳んで出す（食い違いの重い2種が埋もれないように）。

6. 45分専用の科目レコードを廃止する

いま45分の持ち方が2通りある。小学の「国語」「算数」「英語」は 45分版と90分版が別の科目レコードとして登録されている一方、永山校では10/1から 「普通の科目＋パターン側で45分指定」へ切り替える版が既に入っている。 コースが時間を持つなら45分専用の科目は要らないので、廃止して一本化する。

45分科目の参照先件数付け替え
通塾日程パターン16科目IDを90分版へ＋duration_minutes=45
授業コマ130同上
マッチング提案7科目IDを差し替え
指導可能科目（講師）22〜23名45分IDを外す（90分IDは既に入っている）
受講科目・コース・教材・講座・保留授業・テスト対策0影響なし
half_position は触らない（NULL＝全コマ扱いのまま）。 いまも45分の授業はコマを丸ごと使っているので、ここを同時に変えると席の詰まり方が変わる。 前後半の割り当ては後から座席表で設定する。

本丸とは別のマイグレーションに分ける（同じPRだが、単独で適用・巻き戻しできる形にする）。

7. データの持ち方

student_subject_contracts（列を足す）

  • duration_minutes smallint NULL（45 / 90。NULL＝科目マスタに従う＝いまと同じ意味）
    45分専用科目を廃止するので、45分の表現はここだけになる。
  • updated_by uuid（最終変更者）

既存11行は duration_minutes = NULL のまま残す（＝科目マスタどおり）。
テーブル名は変えない。画面での呼び名が「コース」、テーブルは既存名のまま。 コード側のコメントに対応を明記する（本番にあるテーブルを改名すると移行が要るため）。

一括投入はしない。座席表が未稼働で比率欄が誰にも触られていないので、 いまの登録を写しても「全員1対2」という無意味な450件ができるだけ。 コースは座席表の稼働に合わせて、初回登録のときに1回だけ聞いて埋める。

student_subject_contract_changes（新設）

  • school_id / student_id / subject_id
  • from_ratio, from_duration_minutes（初回登録は NULL）
  • to_ratio, to_duration_minutes
  • reason_code（訂正／コース変更／学年切替／初回登録／その他）＋ reason_note
  • changed_by, changed_at

RLS は check_school_access(school_id)（既存のコーステーブルと同型）。 台帳なので authenticated には SELECT / INSERT だけ与え、UPDATE / DELETE は与えない。

8. 触らないところ

  • 保護者ポータルと座席表のバッジは実登録（schedule_entries.ratio）のまま。 コース側に切り替えない。食い違っているときに画面が「1対1」と出て保護者を安心させると、 表示が誤りを覆い隠す装置になる。
  • 席の占有モデル（seatOccupancy.ts）・登録時のブロックはそのまま。
  • 講習の申込フォーム（KoushuEnrollmentFormModal）はコースを既定値として読むだけで 書いていないので、そのまま。読む先が（比率, 時間）の組になるだけ。
  • 既存のコース11行は残す。
