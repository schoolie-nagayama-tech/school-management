# 面談ワークスペースの組み替え（2026-09）

`/interview` の生徒画面を「**上＝話すこと、下＝材料**」に組み替える。
前身の台本の設計は `docs/interview-script-ai-plan.md`、③の定型は `docs/interview-timing-talks.md`。

## なぜ組み替えるか（2026-09-22・教室長の指摘）

- **話すことが材料の中に埋まっている。** いまは左440pxの列に「タスク → 面談記録 →（その中に）申し送り・話すこと・志望校・記録一覧」の入れ子。データと行動の区別が画面に無く、何をすればよいか分からない
- 成績の推移グラフが小さく、合計を0起点の棒で描くので +15点が誤差にしか見えない
- 面談記録は Notta の取り込みを生で貼っていて読めない。空の項目（「確認できませんでした」）が本文の半分を占める
- タスクはほとんど使っていないのに最上段にある

## 決めたこと

### 全体の並び（上から）

| 段  | 中身                                         | 幅             |
| --- | -------------------------------------------- | -------------- |
| 1   | ヘッダー（生徒の切替・氏名・最終面談・印刷） | 全幅           |
| 2   | 帯「話すこと」                               | 全幅           |
| 3   | **面談で話すこと**（InterviewScriptCard）    | **全幅**       |
| 4   | 帯「材料（記録）」                           | 全幅           |
| 5   | 成績 ｜ 面談記録                             | **半々**       |
| 6   | 進行表 ｜ 授業の様子                         | 半々（二次的） |
| 7   | 未完了の約束・タスク                         | 全幅・最下段   |

志望校の入力欄は成績の下（材料側）。④の「聞いて入れる」導線はそのまま。

### 面談で話すこと ―― 項目ごとに 左＝話すこと／右＝事実

> ★2026-09-23 に1列へ改めた（右の事実は各シーンの下に畳む）。いまの形は末尾の
> 「2026-09-23 整理（根拠を畳む・ひとこと・場面・言葉・Notta・検索）」を正とする。以下は当初の決定の記録。

7シーンを①→⑦の順に**縦に**並べ、各シーンを2列にする。**左を上から追えば面談が進む。右はその根拠。**

| 左（話すこと）                                                                       | 右（事実）                                                                         |
| ------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------- |
| 定型行（①③⑥⑦）／聞く（チェック）／AIの見えること／⑤のつながり／見せる物／③の想定問答 | 伝える行（数字）／目標の達成度／志望校との差／入試までの日数・出願〆切／申込の状況 |

- 左は主役（13px・濃い）。右は少し静か（12.5px・薄い背景）
- 列の見出し「話すこと」「事実（記録から）」はシーン一覧の先頭に1回だけ
- ①⑦は右が空。**空のまま**にする（非対称のほうが「ここは言うだけ」と分かる）
- 印刷シートは今回いじらない（すでに2列の紙）

### 右（事実）から材料へ飛ぶ

事実の行の見出し（「定期テスト」「内申」「模試」「進行表」「前回の面談から」）をクリックすると、
下段の該当カードへスクロールする（アンカー＋smooth scroll）。**数字を見て「元を見たい」を1クリックにする。**

### 成績の推移

- 棒→**折れ線**。科目ごとの線＋ドット、凡例
- **縦軸を絞る**（データの最小−5〜最大+5、10刻みに丸める）。注記「縦軸は◯〜◯に絞って表示」を必ず出す
- 合計はスケールが違うので線に混ぜず、表の「5科合計」行と「前回比」列で見せる
- 表に「前回比」列を足す（＋は緑・−は赤）
- rechartsは入れない（前身の判断を維持）。インラインSVG

### 面談記録の読みやすさ

Notta 取り込みを構造化して出す。

- 【タイトル】【録音日時】【音声URL】【参加者】は本文に出さない。音声は右下の「録音を開く ↗」
- 「--- Notta 要約 ---」以降の「■ 見出し」を小見出し、「・」を箇条書きに
- ★**空の項目は畳む。** 箇条書きが「見つかりませんでした」「確認できませんでした」しか無い見出しは、
  末尾に「記載なし：前回の確認・塾からの報告」と1行にまとめる。対象は Notta 由来の定型文だけで、
  手入力の短い記録はそのまま出す
- 既存の `stripNottaMeta` / `extractHandover`（interview.shared.ts）を土台に、パーサを1つ足す

## 中身の追加（第2段）

### ② ヒアリング ―― 「前回こう言ってましたが、その後どうですか」

せっかく来てもらうので、**家庭で見えないことと、良い報告**をここに集める。

右（事実）:

- 前回の面談から ―― 日付・経過日数（既存）
- **前回の約束** ―― 未完了のタスク（`interview_type='task'`）を1件1行。「英語ワークP10まで（未完了）」
- **前回の要望** ―― 直近の面談記録の「保護者からの要望」「次回への申し送り」の箇条書き
- 授業の様子 ―― 引継ぎ N件（**直近3件**を出す。いまは1件）。
  ★**同じ講師・同じ引継ぎ文が続く行は、いちばん新しい1件に畳む**（引継ぎは単元に付くので、
  同じ単元を数回に分けて進めると全部の回に同じ文が乗る。実物で 9/15 と 9/11 が同文だった）。
  ④のLIVE進行表も同じ（`dedupeConsecutiveLessonLines` / `dedupeConsecutiveHandovers`）
- **並びは面談で話す順**：前回の面談から → 前回の約束 → 前回の要望 → 授業の様子 → 宿題・遅刻 →
  目標の達成度。★表示の順であって、AIへ送る順（`BRIEF_SECTIONS`）は変えない

左（話すこと）:

- ★**約束・要望は「聞く」か「報告する」かを中身で決める**（2026-09-23・教室長の指摘）。
  一律に「その後どうですか」と聞いていたが、**保護者からの要望**（「英語の長文を増やしてほしい」）は
  頼まれた側が塾なので、こちらが**対応を報告する**もの。聞き返すと「前に頼んだのに何もしていないのか」になる。
  一方「慶應を含めて最後まで検討」は家庭に**聞く**。「英語ワークP10まで」は記録から追えることもある
- 振り分けは**AIが1件ごとに行う**（`followUps`: `{ item, kind: 'report' | 'ask', text }` を最大6件）。
  - `item` は渡した約束・要望の文そのもの。1字でも違えばパーサが捨てる（AIが言い換えた約束を台本に載せない）
  - `kind='report'`＝記録（引継ぎ・成績・授業の様子）から追えた／塾がしたことを伝えられる。本文が空なら捨てる
  - `kind='ask'`＝記録に無いので家庭に聞く。`text` が空なら画面が「前回の『◯◯』はその後どうですか」を出す
  - `text` にも**数字は書かせない**（seen・bridge と同じ縛り。上限も `MAX_SEEN_LENGTH` と同じ）
- ★**AIが使えない日の受け皿は出どころで振る**（`buildPreviousCommitmentLines` の `items[].source`）。
  「保護者からの要望」の見出しから来たもの → **話す**「報告 ―― 前回の要望『◯◯』への対応を伝える」（中身は教室長が口頭で埋める）。
  約束（未完了タスク）・「次回への申し送り」・「今後の方針」 → 従来どおり**聞く**
- 報告の行はAIが書いた文なので、着眼点（見えること）と同じ枠・同じアイコンで出す。
  ただし**直せない**（着眼点と違い、事実の報告をその場で書き換える場面が無いため。要れば後で足す）
- 印刷シートも同じ規則で振る（報告＝「話すこと」の箇条書き／聞く＝チェック欄）
- AI（見えること）に**授業中のポジティブな報告**を書かせる。プロンプトの lessons の指示に
  「できるようになったこと・授業中の発言・態度の変化を、保護者に伝える良い報告として書く。家庭では見えないことを優先する」を足す
- AI の lastInterview の指示に「前回の約束・要望に対して、その後の記録（引継ぎ・成績）から追えることがあれば書く」を足す

## 教室長レビューの反映（2026-09-23）

### AIの文は枠の中でスクロールさせない

- 見えること（`SeenLine`）の textarea は**中身の高さに合わせて伸びる**（`useAutosizeTextarea`）。
  値が変わったとき・ウィンドウ幅が変わったとき（折り返しが変わる）に測り直す。直せるのはそのまま
- 以前は rows を字数で1〜2行に決め打ちしており、数百字の着眼点が枠内スクロールになっていた
- 報告の行（`ReportRow`）・つながり・つなげて見えることは素の段落なので、もともと全文が出る。印刷シートも全文

### ③時期の重要性は畳める（既定はたたむ）

- ★畳めるのは**③の左だけ**。③は学年×季節×都県の定型と想定問答で、どの生徒でも毎回同じ文。
  台本の中で一番長いのに、読み慣れた教室長には要らない。②④⑤は生徒ごとに中身が変わるので畳まない
- たたんだとき：左は「定型 12行・想定問答 8件を表示」のボタン1つ。右（入試まで・出願〆切）は出したまま
- 開閉はブラウザごとに覚える（localStorage `nest.interview.timingOpen`。読めなければたたむ）
- 印刷シートは常に全部出す

### ④の左で志望校について話す

右に「めやす 必要内申49（+4）・必要偏差値55（-1）」が出ていても、左に言うことが無く、志望校に触れずに終わっていた。
④の左の**先頭**に、志望校ごとの行をシステムが組む（`buildTargetSchoolTalkLines`。AIは使わない。
差はシステムの計算なので数字を使ってよい）。

- 内申：上回る「狛江：内申はめやすを4上回っている。推薦も一般も内申が武器になる」／
  届かない「〜届かない。当日の点で取り返す（換算内申1点は当日の素点で約3点ぶん）」／ちょうど
- 偏差値：上回る「偏差値もめやすを◯上回っている。このまま維持」／届かない「あと◯。次の模試で届く幅かを一緒に見る」
- 組み合わせ：両方プラス→聞く「第1志望として安全圏。上の学校を狙うかを聞く」／
  内申プラス・偏差値マイナス→聞く「推薦を受けるか聞く」／内申マイナス・偏差値プラス→「一般入試の当日点で勝負する形になる」
- マスタに当たらない・本人の内申も模試も無い →「めやすと比べる材料が無い（内申・模試を聞いて入れる）」
- ★差は右の志望校の行と**同じ関数**（`targetSchoolDiffs`）を通す。満点が65でない学校で内申の話をしない決まりも揃う
- ★**神奈川・都県不明の教室は中立な比較だけ**。換算内申の比（都立1020点方式の話）と「推薦」の言葉を出さない
  （神奈川の公立に東京の意味での推薦入試は無い）。比の文言は `scenes.ts` の `TOKYO_NAISHIN_POINT_WEIGHT` 1か所
- 印刷シートは④の右列の先頭に「話すこと」として同じ行を出す
- AIのプロンプト（score）にも「志望校には必ず触れる。推薦・一般のどちらが向くか、内申と当日点のどちらを伸ばすか、
  次の模試で何を見るかを、学校名を出して書く。数字は書かない」を足した

### 前回の要望に Notta の「無い」と論評を拾わない

- `parseNottaSummary` は「確認できません」「発言はありません」「見当たりません」「ありませんでした」「特になし」等で
  **終わる箇条書きを1件ずつ落とす**（以前は見出しの中身が全部それのときだけ畳んでいた）。全部落ちた見出しは従来どおり「記載なし」
- ②の「前回の要望」に拾うときだけ、要望への論評（頭が「要望の強さ」「要望は」「要望としては」、
  または「というより」「レベルです」を含む）を外す。面談記録カードには残す
- ★判定は狭くしてある。要望を取りこぼすほうが害が大きいので、広げるときは実物の文で確かめてから

## ②ヒアリングを 振り返り／学校／塾／家庭 に分ける（2026-09-23）

②は材料が多く、1列に並べると「いま何の話をしているか」が見えなくなっていた（前回の約束の次に部活の話、
その次に宿題の回数…）。保護者との話の順＝**振り返り → 学校 → 塾 → 家庭**に切り、小見出し
（13px太字・左に細い線）の下にいつもの左（話すこと）／右（事実）を置く。モックは承認済み。

| 小見出し | 左（話すこと）                                                                                                                            | 右（事実）                                               |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| 振り返り | 前回の約束・要望への「報告」／「その後どうですか」＋ `lastInterview` の見えること                                                         | 前回の面談から（申し送り）・前回の約束・前回の要望・方針 |
| 学校     | 聞く「学校の授業と宿題の進み具合」「学校の面談で言われたこと」「学校生活の様子（部活動の引退後…）」＋目標の達成度の「結果を聞いて入れる」 | 目標の達成度                                             |
| 塾       | `lessons`・`discipline` の見えること（家庭では見えない塾での様子）                                                                        | 授業の様子・宿題・遅刻                                   |
| 家庭     | `parent` の見えること＋聞く「家庭学習の様子…」「次の定期テスト・模試の目標を決める」                                                      | `parent`（保護者とのやりとり）の行。無ければ空           |

- ★**振り分けはデータで持つ**（`scenes.ts`）。聞くことは `HEARING_GROUPS`、AIセクション→小見出しは

## 2026-09-23 整理（根拠を畳む・ひとこと・場面・言葉・Notta・検索）

### 1列にして、根拠（記録）は畳む（凡例 11）

- シーンの左右2列をやめ、1列（本文幅は 880px まで）。2列だと目が左右を往復し、いま何を言うかが追えなかった
  （★同日、広い画面だけ「左＝話すこと／右＝聞くこと・根拠」の2列にした。下の「広い画面は…」を参照）
- 以前の右の列（事実）は、各シーン・②の各小見出しの一番下に「▸ 根拠（記録）N件」として畳む。
  押すとその場で開き、中身は以前の右の列と同じ静かな枠。見出しを押して材料カードへ飛ぶのもそのまま
- カード右上の「根拠をすべて開く」で全部を開閉。ブラウザごとに覚える（localStorage `nest.interview.factsOpen`、

| 「・印象に残った言葉」 | 見出しを足す前の整形で箇条書きとして保存された記録。知っている見出し名だけの箇条書きは見出しに戻す                                                                                                                                                                        |

同じ PR で、古い型の実物で見つかった読み違いも直した（どれも台本にそのまま出ていたもの）:

- 話し手は「」にいちばん近い語ではなく主語（保護者は／お母様から）を採る（`speakerOfSentence`）。
  「保護者は生徒の現状に…「本当やばいな」」が生徒の言葉になっていた
- 「「…」という外部からの指摘」・「「…」として」は発言として拾わない
- 「次回確認事項：」「合意した対応・変更点：」のような小見出しだけの行を②に拾わない
- 「保護者の感情面：」「保護者・生徒の受け止め：」も見立ての行として扱う。常体の所見（〜様子が見られる。）も前回の要望から外す
- 古い型の【塾】【保護者】【生徒】を誰が動くかとして読む

### 面談記録：Nottaから取り込み＋検索（凡例 14）

- 面談記録カードの見出しに「Nottaから取り込み」。中身は生徒詳細「面談記録」タブと同じ `ImportNottaModal`、
  出し分けも同じ `permissions.canEditInterviews`。取り込んだら面談記録を読み直す（台本の前回の要望・言葉にもすぐ効く）
- その下に検索欄（「面談記録を検索（例：推薦、英検）」）。タイトル＋本文の部分一致で、全角半角・大文字小文字を区別しない
  （`matchesSearch`／`splitForHighlight`。1文字ずつ NFKC を掛けて元の位置に戻せるようにしている）。
  件数を「n件」で出し、当たった所を warning-subtle で塗る（Nottaの見出し・箇条書き・素の本文・前回の申し送り）。
  検索中は当たった記録を畳まずに全部出す。前回の申し送りのピンは絞り込まない

### 広い画面は 左＝話すこと／右＝聞くこと・根拠（2026-09-23 追記・教室長承認）

1列＋880px の上限では、広い画面でカードの右半分がまるごと空いていた。そこで lg（1024px）以上だけ、
シーン・②の各小見出しを2列の格子にする（`renderBlock`）。

- 左（約 1.7）＝(a) ひとこと・(b) 話すこと（定型・見えること・報告・場面・言葉・見せる・つながり・③の想定問答）
- 右（約 1）＝(c) 聞くこと → (d)「▸ 根拠（記録）N件」。開いた根拠も右の列の中に出す（全幅にしない）
- ★旧2列（左＝事実／右＝話す）とは分け方が違う。話す行は左の1列だけを上から追えばよく、
  チェックの行と事実は右に寄せる。「聞くことを話す行の間に挟まない」は変わらない
- 880px の上限は外した。左の1行の長さは列の比で抑える
- 右に置くものが無いシーン（①導入・⑦クロージングなど）は右の列を立てず、左を全幅にする。
  右だけあるときも右の列に置く（場所が毎回同じ方が探せる）
- lg 未満は従来どおり縦に積む（話すこと→聞くこと→根拠）。③の開閉・②の小見出し・根拠の開閉と
  「根拠をすべて開く」・材料へのジャンプ・見えることの編集は変えていない
- 凡例は画面の左→右の順（…見せる → 聞く → 根拠）に並べ替えた

### 「つなげて見えること」を①の上へ（2026-09-23 追記・教室長の指摘）

- AIの `thread`（材料をまたいだ見立て）を、カードの末尾から凡例の直下・①より上・全幅へ移した。
  末尾だと面談前に読まれずに終わっていた。面談全体の芯なので最初に読むものとして置く
- 見た目は info-subtle の地・見出し「つなげて見えること」（11px 太字）・本文 14px。枠線や強い色は足さない
- 空なら何も出さない。印刷シートの位置は変えていない（別の変更で扱う）

### 印刷シート

体裁（2列・A4 1枚）は変えない。前回の言葉は lastInterview の行として「前回の面談から」に乗る。
ひとこと・場面は紙には足さない（メモ欄を 250px まで削ってやっと1枚に収まっているため。面談中に画面で読むもの）。

### ④ テスト対策 → 結果と課題

- 材料: 公開済み（published）の `test_prep_proposals`（新しい順に2件まで）＋科目（`proposed_koma`）＋単元。
  下書きは保護者に出していないので「対策した」と言えない。コマも単元も無い提案書は飛ばす
- ★対策した科目・単元＝**コマを割り当てたもの**。提案書の単元にはテスト範囲がまるごと載る
  （自己評価を付けてから苦手な単元にだけコマを付ける作り。本番の永山校 中3 では英語・数学・国語が
  0コマで単元だけ載っていた）。どの科目にもコマが無い提案書だけ、単元の載った科目を対策とみなす
- 増コマ申込: 提案書の `zoukoma_period_id` → `form_periods.period_key` と同じ期の、この生徒の
  `form_type='zoukoma'` の回答（最新1件・コマ数は請求と同じ `zoukomaKomaCount`）。
  期が付いていない提案書（本番の約半数）は申込の有無を書かない（決めつけない）
- 結果: 試験名 → name_code は目標の達成度と同じ変換表。★**同じ学年**の定期テストだけと突き合わせる
  （本番には去年の term2_mid が111件ある）。提案書を作った年度の学年＝今の学年−年度の差
- 前回: 同じ科目の点がある1つ前の定期テスト。★年度内の順番は `REGULAR_TEST_ORDER` で決め打ち
  （exam_month が6割以上空で、listAssessments の並びが name_code の文字順になるため）
- 根拠（④右）: 「テスト対策（2学期中間）理科 2コマ・社会 1コマ（増コマ申込 2コマ）」
  「→ 結果 理科 64→70（+6）／社会 61→58（-3）」「対策した単元：…（ほかN）」
- 聞くこと: 結果が無ければ「2学期中間の結果を聞いて入れる」。目標の達成度が同じ試験を聞いていれば重ねない。
  試験の種類が付いていない提案書（公開済み57件中15件）は突き合わせない
- AI: score に「テスト対策:」で始まる行を混ぜる。プロンプトに「対策した単元と結果を結び付けて
  効いたところと残った課題を書く（数字は書かない）」。表示側は `stripTargetSchoolFactLines` で外す

### ② 週回数変更 → 変えたあとどうか（塾）

- 材料: 生徒に紐付いた `form_type='shukaisu'` の最新1件（半年以内）。アーカイブ済みも読む
  （処理済みの印で、取り消しではない）
- 根拠（②塾）: 「週回数変更 週2→週3（9月から）実施中／席確定／受付済み」。変更月が来ていれば、
  宿題・遅刻と同じ `computeDisciplineMonthly` の出力から変更後の月（最大3か月）を並べる
- 話すこと: 実施中 →「報告 ―― 週3にしてからの様子を伝える」（塾の話すことの先頭）。
  変更前で座席チェック済み →「10月から週3で席を用意しています」。未 → 聞くことに「確定してよいか確認する」。
  週回数が同じ（曜日・科目の変更）は「週2→週2」と書かない
- AI: lessons はサーバーが引継ぎから組む決まりなので、別の口（`lessonNotes`）で送る。
  サーバーは「週回数変更:」で始まる行しか通さない（`sanitizeLessonNotes`）。引継ぎの**後ろ**に足す
  （前に足すと場面の番号がずれる）。画面の「授業の様子」の行からは外す

### ④ 模試 → 結果を返せているか

- 材料: 生徒に紐付いた `mogi`（Vもぎ）・`moshi`（塾の模試申込）の回答（半年以内）
- 受験日: mogi は選んだ日程ごと（date_id の先頭 YYYY-MM-DD）。moshi は振替なら furikae_date、
  通常なら selected_exam_date。どちらも無い古い回答は、期の日程が1つだけのときに限りそれを使う。
  ★決めきれないものは出さない（推測で「入っていない」と言わない）
- 出す条件: 受験から7日以上・90日以内で、その月以降の模試の成績（category='mock'）が1件も無い。
  成績側の日付は月単位なので月で比べる（同じ月に別の模試が入っていると黙る。誤って黙るほうが害が小さい）
- 根拠と聞くこと（④）: 「都立Vもぎ 9月の結果がまだ入っていない（返却を確認）」。入っていれば何も出ない
- 模試の申込がある生徒には「模試を受けているか聞く」を出さない（テスト対策の結果を聞くときの
  「定期テストの結果を聞いて入れる」も同じ）

### 印刷シート

件数は `printCaps.ts` で絞る（testPrepFacts 2・applicationAsks 1・shukaisu 1）。

## 通学時間の起点＝教室の最寄り駅（2026-09-24・下準備）

志望校までの通学時間の目安（直線距離・自転車の分数）を面談に出すための下準備。
画面への表示は次の段で、ここでは起点のデータと計算の部品だけを入れた。

- **起点は教室の最寄り駅。★生徒の住所は使わない。** 住所を持つと個人情報の扱いとAIへの送り方まで
  広がる。同じ教室の生徒は生活圏がほぼ重なるので、目安としてはこれで足りる。
- 持ち場所: `schools.nearest_station`（「駅」なし）／`nearest_station_lat`／`nearest_station_lon`
  （`supabase/migrations/20260924120000_schools_nearest_station.sql`）。

  （教室長以上）が国土地理院の地名検索を引く。★title が「◯◯駅」と完全一致した地物だけを採る
  （部分一致だと駅前の郵便局・交番の座標になる）。見つからなければ手入力。駅名を変えたら緯度経度は消す。
- 計算: `src/lib/geo/distance.ts` の `haversineKm`（直線）と `estimateBikeMinutes`（15km/h・切り上げ）。
  ★直線距離に係数を掛けて道のりに見せかけない。画面では「直線」「目安」と必ず添える。
- ★リポジトリには国土数値情報 N02 の生データが無い（`docs/data/toritsu-school-station-r7.csv` は駅名と距離だけ）。
