## 0. 何をするか

いまの「今日やること」は**一覧**で、上から順に見て自分で段取りを組む。
そこに **時間帯への割り付け** を足す。授業前／3限／4限／5限／片付け に置き、
21:30 に収まらないものは「いつやるか」まで指定して外へ出す。

**出てくるのは読み物ではなくタスク。** チェックして消し、文字を直し、
ドラッグで別の時間帯へ動かし、AIが出していない用事を足せる。
**AIが出すのは案で、決めるのは教室長。**

## 1. ★2段構え

|           | いつ                   | 何をするか                           | AIの役目               |
| --------- | ---------------------- | ------------------------------------ | ---------------------- |
| **1段目** | **毎朝 10:00（cron）** | その日の材料を全部読んで段取りを組む | 全体の割り付け         |
| **2段目** | 日中、用事が増えるたび | **1件だけ差し込む**                  | **入れ場所だけ**決める |

**なぜ分けるか**: 朝に組んだ段取りは日中に必ず崩れる。そのたびに全部組み直すと、
**消したものや、ドラッグで直した並びが吹き飛ぶ**。2段目は既存の段取りを一切いじらず、
`{block, when, why}` だけを返して1件を差し込む。

- 1段目: `vercel.json` の cron に1本足す（10:00 JST＝`0 1 * * *` UTC）。
  結果はその日ぶんだけ保存する（教室×日付で1行）。
- 2段目: `POST /api/ai/today-plan/place`。いまの段取りと材料を渡し、入れ場所だけ返させる。

## 2. 材料（すべて既存のデータ）

| 材料                 | 取得元                                      | 備考                                                                                                                                                        |
| -------------------- | ------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 今日やること         | `src/lib/api/todayTodos.ts`（実装済み）     | 教材の配布待ち・面談・問合せ・報告書など                                                                                                                    |
| **Googleカレンダー** | **既存の連携をそのまま使う**                | `google_calendar_tokens` ＋ `listCalendarEvents(userId, timeMin, timeMax)`。業務進捗管理（`/api/courses/progress/sync-calendar`）が既に同じ経路で読んでいる |
| 月次タスク           | `monthly_tasks` ＋ `monthly_task_checks`    | ★段取りからは直接引かない。「今日やること」に入って渡ってくる（§7）                                                                                         |
| 今日の授業           | `schedule_entries` ＋ `schedule_time_slots` | コマの時刻は教室ごとに違う（永山は 3限16:20-17:50／4限17:55-19:25／5限19:30-21:00）                                                                         |
| この先の空き具合     | `schedule_entries`（翌日〜数日）            | **授業の登録が無い日には回さない**ための材料                                                                                                                |

生徒・講師は**姓のみ**。氏名・連絡先はAIに渡さない。

## 3. AIに守らせること（プロンプトに固定）

- 1日は **21:30 で終わり**。それ以降の時間帯を作らない。
- **生徒に渡す用事は、その生徒が来るコマに置く**（帰ってからでは渡せない）。
- **カレンダーの予定が入っている時間帯には用事を置かない。** 予定そのものも項目として出し、
  その時間に何があるかが分かるようにする。
- **カレンダーで来塾する人がいるなら、その人に渡すものはその時間に置いてよい**
  （授業に来ない生徒でも、面談で来るなら渡せる）。
- 締切が先の月次タスクは、空きがあれば前倒してよい。置くときは why に締切日を書く。
- 21:30 に入らないものは `tomorrow` に出し、**授業の登録が無い日を避けて**いつやるかまで指定する。
- データにない予定を作らない。項目を増やさない。
- 各時間帯 0〜4件。置いた理由を短く1行（why）添える。

## 4. 画面（タスクとして扱う）

- チェック → 済（打ち消し線）。上に「残り N 件／全 M 件」。
- 本文は **その場で書き換えられる**（contenteditable）。
- **ドラッグ&ドロップで並べかえ・別の時間帯へ移動**。つまむのは取っ手（⠿）だけにする
  （行全体を draggable にすると本文の文字が選べなくなる）。
- × で消す。時間帯ごとに「＋ 追加」。
- 直した結果が正典。描き直しても消えない。

## 5. 実データで確かめたこと（永山校・2026-09-03木）

モックは作り話ではなく永山校の実データで動かしている。分かったこと:

- **教材の配布待ちが11件**あり、最も古いのは **7/17納品＝48日経過**。
  そのうち今日の授業に来るのは3名だけ。**残りは「いつ渡すか」を決めないと消えない。**
- **カレンダーの面談で来塾する生徒がいる**（授業には来ない）。
  → 面談のついでに教材を渡せる。**材料をまたいで初めて出てくる判断**で、一覧を眺めているだけでは気づけない。
- **9/5・9/6は授業の登録が無い**。「明日でいいか」を判断するには、この先の空き具合が要る。
- 面談から1か月を超えた生徒が6名。全員に今日声をかけるのは無理なので、**今日は誰にするか**の判断が要る。

> 講師未定のコマが24件あったが、これは**座席表をまだ運用していないため**で、実務上の穴ではない。
> 材料からは外した。

## 6. 足りていない材料: 勤務の時間（2026-09-03 指摘）

いまの材料には**誰が何時にいるか**が入っていない。これが無いと、

- 教室長がその日いない時間に用事を置いてしまう
- 「講師に伝える」用事を、その講師が出勤していない時間に置いてしまう
- 授業前と言っても、実際の出勤時刻より前には何も置けない

すでにデータはある（／出勤簿／ の担当）ので、
**出勤の開始・終了時刻を材料に足す**。1段目のcronでも2段目の差し込みでも同じように効く。

**★既定は 13:00〜21:30（2026-09-03 ユーザー決定）。** 出勤簿・シフトに時刻が無い日はこの枠で組む。
時刻がある日はそちらを優先する。用事はこの枠の外に置かない。

## 7. ★材料は「今日やること」そのもの（2026-09-09 決定）

当初はサーバー側（`src/lib/ai/todayPlanMaterials.ts`）で `material_orders` と `monthly_tasks` を
引き直していた。理由は「`fetchTodayTodosLight/Heavy` がモジュール読み込みだけで
ブラウザ用の supabase クライアントを掴むのでサーバーから呼べない」から。

**やめた。** 別々に集めると、同じ画面の上（段取り）と下（今日やること）で違う用事が並び、
どちらが正しいのか分からなくなる。いまは下のウィジェットが読んだ `TodayTodoItem[]` を
そのまま上へ渡し、API（`generate` / `place`）の body で受け取る。

- 受け取ったものは信用しない。`sanitizePlanTodos`（`src/lib/ai/todayPlan.ts`）が1件ずつ検め、
  **生徒はここで姓だけに落とす**。読めない要素は1件ずつ捨てて残りを使う（最大100件）。
- 材料に載せるのは50件まで。**切るのは重要でないものから**（期限超過 → 急ぎ → 時限あり の順で残す）。
- `TodayTodoItem` は `slotNumber` を持つので、**AIが「どのコマに来る生徒か」を推測する必要がない。**
- 下がまだ読めていないあいだは「今日の段取りを組む」を押させない。
  空のまま組むと空の段取りが保存され、その日はもう組み直せなくなる。

カレンダーは §2 のとおり既存の連携（`listCalendarEvents`）をそのまま使う。
**未連携・取得失敗は握って空にする**（カレンダーのせいで段取りが作れなくなってはいけない）。
終日の予定は外す（時間帯が決まらず、00:00〜23:59 として渡すと1日ぶんの用事が行き場を失う）。

## 8. 残っていること

- 1段目の cron（いまは画面のボタンから朝1回）。
- 「済」の保存。いまのウィジェットは localStorage（`nest.todayTodos.done.${today}`）。
  段取りも同じ方式でよいか、DBに持つかを決める。
- 出勤簿・シフトの時刻を勤務の枠に反映する（§6。いまは 13:00〜21:30 の既定固定）。
