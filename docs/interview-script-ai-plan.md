# 面談で話すことを、面談の流れ順に組む（設計書）

作成: 2026-09-18 ／ 状態: **設計中（モック未）**
対象: `src/app/interview/`（面談ワークスペース）
前身: [docs/interview-brief-ai-plan.md](./interview-brief-ai-plan.md)（「報告事項」カード・PR #168）

## 0. 何をするか

講習面談の直前に、その生徒についてNESTにあるデータから**面談で話すこと**を組む。
並びは本部チェックリストの7シーン（①導入〜⑦クロージング）。

いまの「報告事項」カードは**データの種類順**（成績／授業の様子／宿題…）で、
面談の席では「どの順に何を話すか」に組み替える手間が残っていた。これを**面談の流れ順**にする。

## 1. 決めたこと（2026-09-18）

1. **対象は講習面談・全学年。** ③の定型トークは学年×季節で差し替える。
   講習の期が動いていないときは⑤⑥を出さない（結果として通常の面談にも使える）。
2. **箇条書きが本体。** 話し言葉の台本は試作を見てから採否を決める（§6）。
3. **「報告事項」カードは廃止して一本化。** 中身は②④⑤に吸収する。AIのボタンは1つ。
4. **数字はシステムが組む。AIが書くのは着眼点だけ。** 前身の原則をそのまま引き継ぐ
   （[[構想_AIは書かせず整える]]）。AIが数字を書き直しても画面に出ない構造にする。
5. **データが無い項目は「聞くこと」として出す。** 欄を足すのは志望校だけ。
6. **高校の偏差値・倍率マスタは第2段。** 第1段は志望校名と本人の数字を並べるところまで。

## 2. 1行の種類

シーンの中の各行は、次の4種類のどれか。画面ではアイコンで区別する。

| 種類 | 誰が作る | 例 |
| --- | --- | --- |
| 伝える | システム（数字・事実） | 「1学期期末 5科 312点（前回比 +18）」 |
| 着眼点 | AI（1文40字まで） | 「上がったのは数学だけ。英語は2回続けて下がっている」 |
| 聞く | システム（データが無い項目の定型） | 「家庭学習の様子」「学校の面談で言われたこと」 |
| 見せる | システム（手元に用意する物） | 「PCS結果表（回収済み）」「講習プラン表」 |

## 3. シーンごとの中身と材料

### ① 導入 — 定型のみ

謝意／目的と内容／所要時間。生徒データは使わない。AIも使わない。

### ② ヒアリング

| 行 | 種類 | 材料 |
| --- | --- | --- |
| 前回の要望・約束とその後 | 伝える＋着眼点 | `student_interviews`（`extractHandover`）、保護者チャット直近10件 |
| 目標の達成度 | 伝える | `student_textbook_exams`（`target_score` vs `result_score`）、`action_goals` |
| IEでの授業の様子 | 伝える＋着眼点 | `class_reports.review_comment`・正答率、`progress_sessions.handover` 直近20件 |
| 宿題・遅刻 | 伝える | `progress_sessions`（`computeDisciplineMonthly`・分母「授業N日」を添える） |
| 部活 | 伝える | `students.club` |
| 家庭学習／学校の授業・宿題／学校の面談の内容／講師について | 聞く | なし |
| 希望進路・志望校（第1・第2・理由） | 伝える or 聞く | **新設**（§4）。未入力なら「聞く」に回り、その場で入力できる |
| 直近の目標設定 | 聞く | 次の定期テスト・模試の目標。決まったら既存の目標入力へ |

出欠（`schedule_entries.attendance_status`）は本番でほぼ空なので、前身と同じく使わない。
座席表の運用が始まったら足す。

### ③ 時期の重要性 — 定型＋日数だけ

- 入試（または学年末）までの日数。
- 学年×季節の定型トーク（年間学習計画、この時期の意味、夏と冬の違い、家庭・学校・IEでやること）。
- **AIに書かせない。** 毎回同じことを言う場所なので、テンプレートをコードに持つ
  （`src/lib/interview/scriptTemplates.ts`）。
- ★手元にあるのは中3夏期のチェックリストだけ。他の学年・季節の定型は**未入手**（§8）。

### ⑤ プラン提示

| 行 | 種類 | 材料 |
| --- | --- | --- |
| プランのねらい | 伝える | `seasonal_proposals.theme`（複数行） |

書類を渡す／報告カウンセリングの告知／紹介の案内／謝意／見送り。

### 面談全般（声の大きさ・姿勢など）

話し方の自己点検であって話す内容ではない。**画面には出さない。** 印刷シートの末尾に小さく載せるかはモックで判断。

## 4. 志望校と高校マスタ（新設）

### 4-1. 志望校

`students` に列を足さず、別テーブルにする。

```
student_target_schools
  id, school_id, student_id,
  rank smallint              -- 1=第1志望, 2=第2志望
  school_name text           -- 入力された学校名（都立以外もあるので自由記述を残す）
  high_school_id uuid null   -- マスタに当たればFK。当たらなければNULLのまま
  reason text
  updated_by, updated_at
  unique (student_id, rank)
```

- 学校名は自由記述で持ち、マスタに当たったときだけ `high_school_id` を埋める。
  **私立・国立・他県はマスタに無い**ので、FKを必須にすると入力できなくなる。
- RLSは教室スコープ。★既定権限で `anon` / `authenticated` に ALL が付くので、revoke してから付け直す。
- 入力場所は2つ: 面談画面の②（その場で聞いて入れる）と、生徒詳細。
- 本番DDLは Supabase MCP の `apply_migration`。

★**`school_id` は BEFORE トリガーで生徒の所属校に強制する**（`trg_student_target_schools_sync_school`・
本番適用済み）。この列は RLS が見る唯一の列で、生徒の所属校とズレるとその行は担当の講師から
見えなくなる。所持教材（`student_textbooks`）で同じ事故を起こしており、あちらも
`sync_student_textbook_school_id` で同じように塞いである。
別教室の `school_id` を渡して矯正されることを本番で確認済み。

### 4-2. 高校マスタ（★本番適用済み・2026-09-21）

**本番DBに適用し、205行を取り込み済み。** マイグレーションは
`supabase/migrations/20260921120000_high_schools.sql` と `..._student_target_schools.sql`。
取込は `node scripts/import-high-schools.mjs --go`（`--go` なしは下見）。

- `high_schools` 205行 ／ `high_school_standards` 205行（すべて `verified_at` は NULL＝未確認）
- 沿線が入ったのは203行。付かない2行は産業技術高専（所在地データが無い）と
  大島海洋国際（離島で鉄道なし）
- 最寄駅を公式サイトで確認して上書きしたのは12行
- セキュリティ診断（`get_advisors`）で本3テーブルに関する指摘は無し。
  anon には権限が1つも残っていないことを `information_schema.role_table_grants` で確認済み

材料は `docs/data/` に揃っている（出どころと注意は [docs/data/README.md](./data/README.md)）。
**学校そのもの**と**年度ごとに変わるめやす**を分ける。めやすは毎年更新され、
過去の面談で示した数字を後から再現できる必要があるため。

```
high_schools                        -- 学校×学科。めやす表の1行に対応
  id uuid
  prefecture text                   -- '東京都'（将来 神奈川県 を足す）
  school_name text                  -- '小平'
  course text                       -- '外国語'。普通科本体は空
  category text                     -- '普通科' '工業科（工科）' など
  school_code text null             -- 都教委の学校番号。産業技術高専はNULL
  old_district smallint null        -- 旧学区。普通科のみ
  municipality text null
  address text null
  lat, lon numeric(9,6) null
  primary_station text null         -- ★保護者に「最寄駅」として見せない（直線距離）
  primary_lines text[] null
  access_lines text[] null          -- 沿線での絞り込みはこれを使う
  station_source text null          -- '算出' / '手動' / '鉄道なし' / '座標なし'
  location_source text              -- '都教委 令和7年度 公立学校一覧'
  unique (prefecture, school_name, course)

high_school_standards               -- 合格めやす。版ごとに1行
  id uuid
  high_school_id uuid -> high_schools
  source text                       -- '進学研究会Vもぎ'
  source_year smallint              -- 2026（令和8年度受験用）
  source_label text                 -- 'Vもぎ 2025年9月版'。画面に出す出典表記
  total_score smallint              -- 1000点満点・合格可能性60%
  naishin smallint
  naishin_max smallint              -- 65 / 75 / 52
  hensachi smallint
  exam_type text                    -- '共通' / '自校作成'
  gakuryoku_ratio text              -- '7:3' / '6:4'
  note text
  verified_at timestamptz null      -- ★紙と突き合わせた日。NULL=未確認
  unique (high_school_id, source, source_year)
```

**`verified_at` を必ず持つ。** めやすの数値は紙からの手起こしで、まだ突き合わせが済んでいない。
未確認の数字を保護者に見せる画面に出すときは、その旨が分かるようにする。

取込は `docs/data/` の4つのCSVを読む1本のスクリプトにする（seed ではなくワンショットの取込）。
結合は §全体の作り（README）のとおり。

### 4-3. おすすめ学校を出すとき

- 絞り込み: 都県 → 沿線（`access_lines`）または市区町村 → 内申 → 偏差値。
  ★`naishin_max` が 65／75／52 と混在するので、満点の違う行を混ぜて比較しない。
  画面に内申を出すときも、満点が65以外なら分母を添える（「必要内申55/75」）。
- ★**緑園都市校は横浜市泉区**で、通塾圏は神奈川県立が主。都立マスタだけでは足りない。
  第1段では「この教室は対象外」と正直に出す。神奈川のめやすは紙の資料待ち。
- ★**最寄駅を「学校の最寄駅」として保護者に見せない。** 直線距離なので実態と食い違う
  （README の永山高校の例）。沿線で候補を絞るところまでに使う。

## 5. PCS・ETS の取り方

結果の帳票はNESTに無い。講習進捗表に「PCS回収」列があり（`CourseProgressWidget.tsx` が
`findItemByKeywords(items, ['PCS回収', 'PCS'])` で拾っている）、生徒ごとの済／未が取れる。

- 回収済み → ④⑤に「見せる: PCS結果表」。
- 未回収 → ⑤に「PCS未回収。結果を根拠に使えない」。
- 列が無い期・教室 → 何も出さない。

ETSも同じ拾い方（キーワード `ETS`）。列が無ければ黙る。

## 6. AIの入出力

前身（`src/lib/ai/interviewBrief.ts`）の構造を、セクション単位からシーン単位に置き換える。

```json
{
  "points": [
    { "scene": "hearing", "row": "lessons", "seen": "英語の引継ぎに『単語が抜ける』が4回", "sign": "warn" }
  ],
  "thread": "英語だけ、成績・宿題・引継ぎが同じ方向を向いている。",
  "bridge": "英語の単語不足 → プランの英語8コマ（単語・文法の復習）につながる"
}
```

- `points[].seen`: その行から見えること。1文40字まで。無ければ出さない。
- `sign`: `warn` / `good` / 空。
- `thread`: 複数の行をつなげて初めて見えること。1文。
- `bridge`: **④の課題と⑤のプランのつながり**を1文。講習面談の核なので独立させる。
  提案書が無ければ空。
- 前身の `talk`（話す項目3〜5個）は廃止。シーン順そのものが「話す順」になるため。

プロンプトの決まりは前身の§4を引き継ぐ（無いことを足さない／数字を書き直さない／
悪い話だけにしない／無ければ空）。栓は前身と同じ `student_digest`。モデルは Haiku。

### 話し言葉の台本（試作）

箇条書きを出したあと、「台本にする」ボタンでシーンごとに話し言葉へ展開する。
**別の呼び出し**にして、箇条書きの品質に影響させない。採否はユーザーが試作を見て決める。
採用しない場合はボタンごと消す。

## 8. 未決・ユーザーに確認すること

1. **他の学年・季節のチェックリスト（または定型トーク）はあるか。** 中3夏期しか手元に無い。
   無ければ受験学年／非受験学年の2系統×3季節を、中3夏期を元にこちらで下書きして見てもらう。
2. **入試日をどこに持つか。** ③の「入試までN日」に要る。都立一般・私立・中学入試・共通テストで違う。
   案: 年度ごとの定数をコードに持つ。
3. **支払い方法・期限、日程表の締切。** 期ごと・教室ごとに違うなら講習の期の設定に欄が要る。
   同じなら定型文でよい。
4. 志望校をAIに送る。プライバシーポリシー第5条の2の送信項目の書き方に収まるか確認する。
5. **合格めやすの二次利用。** 進学研究会の資料をシステムに取り込んで画面に出すことの可否。
   利用条件を確認する（未確認）。教室内の参考値としての利用で、出典と版を併記する前提。
6. **めやすの数値を紙と突き合わせる。** 学校名と旧学区は公式データで裏が取れたが、
   得点・内申・偏差値は未確認（README の §確認が要る行）。
