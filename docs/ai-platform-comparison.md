# NEST への AI 機能導入：呼び出し基盤の比較検討

作成日: 2026-09-01 / 前提: Next.js 14 (App Router) + Supabase + Vercel、TypeScript

> 本書の価格・仕様はすべて 2026-09-01 時点で公式ドキュメントを参照して記載している。出典は §7 に一覧。
> 為替は **1 USD = 150 円** で換算している（実際の請求は各社のレートによる）。

---

## 1. 結論

- **Anthropic Claude API（Haiku 4.5 を主力、Sonnet 5 を難所だけ）を直接叩く構成**を推す。月額 ¥1,100〜2,300 程度で、3ユースケースすべてを賄える。
- 理由は価格ではない（どれを選んでも月 ¥3,000 未満）。**API に送った内容を既定で保存しない**（学習利用もしない）のは Claude API だけで、生徒の氏名・成績を扱う本システムでは説明責任がいちばん軽い。
- **Google Workspace 契約から自社アプリで Gemini を呼ぶことはできない**（§2）。Gemini を使うなら Google Cloud の別契約・別課金になる。

## 2. Google Workspace から引っ張れるのか

### 答え: **いいえ。引っ張れない。**

Google Workspace の Gemini は「**Workspace の各アプリ（Gmail / Docs / Sheets / Meet 等）の中で人が使う機能**」として提供されている。Workspace の契約は、外部の自社アプリケーション（NEST の Next.js サーバー）から Gemini モデルを API 経由で推論に使う権利を含まない。

Workspace のプラン料金（日本の公式価格ページ、ユーザーあたり月額）は次のとおり:

| プラン | 月額/ユーザー | AI に関する記載 |
| --- | --- | --- |
| Business Starter | ¥800 | 「Gmail の Gemini AI アシスタント」「Gemini アプリでの AI チャット」 |
| Business Standard | ¥1,600 | 「Gmail、ドキュメント、Meet などの Gemini AI アシスタント」「複雑なタスク向けの Google の最も高性能な AI モデル」 |
| Business Plus | ¥2,500 | Standard と同等の Workspace 内 Gemini ＋ Gemini アプリの拡張アクセス |
| Enterprise | 要問い合わせ | 上記に加え全 AI ツール／モデルへの拡張アクセス |

（出典: [workspace.google.com/pricing](https://workspace.google.com/pricing)。2024〜2025 年にかけて Gemini Business / Gemini Enterprise アドオンが基本プランへ統合された経緯は §7 の参考リンクを参照）

いずれも「**Workspace アプリの中の機能**」の話であり、料金表に API クォータやトークン枠の記載はない。

### では何が必要か

自社アプリから Gemini を呼ぶには、Workspace とは**別に**次のどちらかを契約する:

1. **Gemini Developer API（Google AI Studio）** — API キーを発行し、Google Cloud の請求先アカウントに従量課金。個人開発〜小規模向け。
2. **Vertex AI / Gemini Enterprise Agent Platform（Google Cloud）** — GCP プロジェクト上で使う。リージョン指定・IAM・監査ログなどエンタープライズ向けの制御が付く。

**どちらも Workspace の料金とは完全に別建て**で、Workspace を契約していても割引や無料枠は付かない。「すでに Workspace を払っているぶんで賄える」という期待は、残念ながら成立しない。

### Apps Script 経由という抜け道について

Apps Script から `UrlFetchApp` で Gemini API / Vertex AI を呼ぶことは技術的には可能だが、**結局呼ぶ先は上記 1 か 2 であり、課金は同じく別建て**になる。加えて実務上のデメリットが大きい:

- 実行時間の上限（1 実行あたり数分）と 1 日あたりの実行時間クォータがあり、NEST の想定件数では詰まりやすい
- ストリーミング応答が扱えない（講評の下書きは「書かれていく」見え方が UX 上効く）
- NEST の認証・RLS の外側に処理が出るため、生徒データの持ち出し経路が一本増える
- TypeScript の型が効かず、NEST 本体のコードベースから分断される

**Apps Script は採らない**ほうがよい。

### 4.4 この試算から読み取れること

**コストは意思決定材料にならない。** 最安（¥73）と最高性能クラス（¥3,098）の差は月 ¥3,000 で、講師 1 名の時給にも満たない。**「安いから Flash-Lite」ではなく「講師が手直しせずに済む品質か」で選ぶべき**で、品質が低くて講師が全文書き直すなら月 ¥3,000 の節約は完全に逆ざやになる。

さらに下げる余地（必要なら）:

- **プロンプトキャッシュ**: 3 ユースケースとも system prompt（塾の方針・文体ルール・出力フォーマット）が共通で長くなる。Claude のキャッシュ読み出しは基本入力の 0.1 倍なので、入力側が実質 1/10 近くまで落ちる。②の 2,000 コール/月なら効果が大きい。
- **バッチ API（50% 引き）**: ①「今日やること要約」は夜間に一括生成しても成立するのでバッチ向き。②③は対話的なので不可。

**上振れ要因**（試算より高く出る方向）:

- **日本語はトークン効率が悪い**。「入力1,500トークン」の前提が実際は 2,000〜2,500 になる可能性がある。1.5 倍を見ておくと安全。
- **Claude Sonnet 5 は新しいトークナイザ**を使っており、同じ文章で約 30% 多くトークンが出る（Haiku 4.5 は旧トークナイザ）。Sonnet 5 の実額は ¥2,900 前後を見ておく。
- **Gemini 3.7 / 3.6 Flash は 2027-01-01 に価格が倍**（$1.50 → $7.50）になることが公式に告知済み。3.7 Flash の ¥847 は 2026-12-31 までの導入価格で、2027 年からは **¥1,693**。

## 5. データの扱い・個人情報の論点

### 5.1 各社の既定の扱い（公式記載）

| 提供元 | 学習利用 | 既定の保持 | ゼロデータ保持 |
| --- | --- | --- | --- |
| **Anthropic** | 「Retained data is never used for model training without your express permission」 | **会話内容（プロンプトと出力）は既定で保持しない**。例外は Covered Models（Fable 5 / Mythos 5）で 30 日保持 | ZDR あり。営業窓口経由で組織単位に有効化 |
| **OpenAI** | 「Data sent to the OpenAI API is not used to train or improve OpenAI models (unless you explicitly opt in)」 | **不正利用監視ログを既定 30 日**保持 | ZDR あり。ただし事前承認と追加条件の受諾が必要 |
| **Google（Gemini API）** | **有料ティアは学習に使わない／無料ティアは使う**（公式価格表に「Data used to improve products（Free）」「Data not used to improve products（Paid）」と明記） | 未確認（本調査では保持期間の公式記載を特定できず） | 未確認 |

この表でいちばん効くのは **Anthropic だけが「既定で会話内容を保存しない」**という点。OpenAI は既定 30 日、Google は保持期間を本調査では確認できていない。保護者への説明や委託先監督の観点では、追加交渉なしで最初から保存されない構成がいちばん軽い。

**注意**: Gemini API の**無料ティアは入力が Google のプロダクト改善に使われる**と公式に明記されている。試作段階でうっかり無料キーで生徒データを流すのは事故なので、**最初から有料ティアで始めること**。

### 5.2 日本の個人情報保護法まわり

NEST が AI 提供元へ生徒の氏名・成績・出欠を送る行為は、**「個人データの取扱いの委託」**（法27条5項1号）として整理するのが自然で、その場合は第三者提供の同意は不要になる。ただし提供元が外国事業者なので、**法28条（外国にある第三者への提供）**と**安全管理措置の一環としての「外的環境の把握」**が論点になる。個人情報保護委員会も生成AIサービス利用について注意喚起を出しており、要点は次の3つ:

1. **利用目的の範囲内か** — 「授業報告書の作成補助」「保護者対応の補助」が現行のプライバシーポリシーの利用目的に読み込めるか確認する。読み込めないなら利用目的を追記する。
2. **入力データが機械学習に利用されないことの確認** — §5.1 のとおり、有料ティアであれば主要3社とも学習利用しない旨を公表している。この確認記録を残す。
3. **委託先としての監督** — 契約（各社の Commercial Terms / DPA）で日本法相当の水準が担保されるようにする。

### 5.3 NEST 側で必要になる実務対応

`docs/legal/privacy-policy.md` 第5条の**委託先一覧に AI 提供元を追記する必要がある**。現状の表は次のようになっている（Supabase / Vercel / LINEヤフー / Resend / Google LLC / Slack / Notta）。ここに 1 行足す:

```
| Anthropic PBC | 米国 | 授業報告書の講評案・返信案の生成補助（入力内容は学習に利用されず、既定で保存されません） |
```

同ファイル末尾のチェックリストにも「第5条の委託先一覧が、公開時点で実際に利用しているサービスと一致しているか」という項目があり、これに引っかかる。**公開前に必ず更新すること。**

### 5.4 仮名化はすべきか

**結論: 氏名は送らないほうがよいが、完全な仮名化パイプラインまでは要らない。**

ユースケース別に見ると:

- **① 今日やること要約** — 生徒名を出さないと要約の意味が薄い（「田中さんの振替確認」）。ただし**姓のみ**で足りる。学年・成績は不要なので送らない。
- **② 報告書の講評下書き** — ここが本命だが、実は**氏名は要らない**。単元・達成度・テスト結果と、あとは「学年」「呼称（さん/くん）」があれば講評は書ける。**氏名を送らずに生成し、講師が確認する画面で氏名を差し込む**設計にすれば、外部に出る個人情報を大幅に減らせる。これは実装コストもほぼゼロ。
- **③ 保護者チャット返信** — 保護者の文面をそのまま渡す必要があるので、氏名が混ざるのは避けられない。ここは仮名化を諦め、委託として整理する。

つまり**②だけ氏名を落とす**という部分的な対応が、費用対効果がいちばん高い。全ユースケースを通す共通の仮名化レイヤーを作るのは過剰。

**送ってはいけないもの**（どのユースケースでも）: 生徒・保護者の住所、電話番号、メールアドレス、LINE のユーザーID、支払い情報。プロンプト組み立て関数の側で、渡すフィールドを**ホワイトリストで明示的に列挙**する（`select('*')` の結果をそのまま流さない）。

## 6. 推奨構成

### 6.1 構成

```
Next.js Route Handler (/api/ai/*)
  └─ Vercel AI SDK (ai + @ai-sdk/anthropic)
       └─ Claude API
            ├─ Claude Haiku 4.5   … ①今日やること要約 / ②報告書の講評下書き
            └─ Claude Sonnet 5    … ③保護者チャット返信、②の「提出前チェック」
```

- **鍵は Vercel の環境変数**（`ANTHROPIC_API_KEY`）に置き、**サーバー側の Route Handler からのみ呼ぶ**。クライアントから直接 API を叩かない。
- 既存の `fetchWithAuth` / `getApiAuth` の作法に合わせ、`/api/ai/**` も認証必須にする（教室スコープの検証も入れる）。
- ストリーミングは AI SDK の `streamText` を使う。②の講評は「書かれていく」見え方があると講師の待ち時間の体感が大きく変わる。

### 6.2 なぜ Claude を推すか

1. **データの扱いがいちばん軽い** — 既定で会話内容を保存しない。ZDR の交渉も、30 日保持の説明も要らない。生徒データを扱う塾システムでは、これが最大の差。
2. **コスト差が無視できる** — Haiku 4.5 で月 ¥1,129。Gemini Flash-Lite との差は月 ¥1,000。この差で判断する理由がない。
3. **日本語の講評文の質** — ②③は「保護者に見せる日本語の文章」なので、文体の自然さが直接効く。最安モデルで妥協すると講師の手直し時間が増え、AI を入れた意味が薄れる。まず Haiku 4.5 で試し、質が足りなければ Sonnet 5 に上げる（月 ¥2,300 で済む）。
4. **Workspace 経由が使えない以上、Google を選ぶ理由が消える** — 「すでに払っているから安い」が成立しないなら、Gemini は「別契約の外部 API」という点で Anthropic / OpenAI と同列になる。それなら上記 1 の差が効く。

### 6.3 Vercel AI SDK を挟む理由

直接 `@anthropic-ai/sdk` を使ってもよいが、AI SDK を挟むと**プロバイダの差し替えが 1 行**になる（`anthropic('claude-haiku-4-5')` → `google('gemini-3.7-flash')`）。本件は「どのモデルが日本語の講評に向くか」を実際に走らせて比べたい性質のタスクなので、**比較のしやすさそのものが価値**になる。AI SDK の詳細と Vercel AI Gateway の要否は §6.5 を参照。

### 6.4 段階的な進め方

1. **②の報告書講評だけ**で始める。いちばんボリュームが大きく、効果が見えやすく、氏名を落とせるので個人情報リスクも最小。
2. 内部フラグ（admin 限定）で数週間回し、**講師が採用した割合／手直し量**を測る。
3. 質が出たら①③へ広げる。同時にプライバシーポリシーの委託先一覧を更新して公開する。
4. **月次の使用量アラート**を入れておく（想定 2,550 コール/月。桁が違ったらループかリトライ暴走を疑う）。

### 6.5 実装上の注意

- **Vercel の Function 実行時間上限**に注意。ストリーミングしない長い生成はタイムアウトしうる。Route Handler に `maxDuration` を明示する。
- **リトライとフォールバック**: 429 / 5xx は指数バックオフで 2 回まで再試行し、それでも駄目なら「AI 下書きは今回使えません」と出して**講師が手書きできる状態に必ず戻す**。AI が落ちても業務が止まらないことが最優先。
- **プロンプトは DB ではなくコードに置く**（バージョン管理して差分を追えるようにする）。文体ルールの調整が必ず何度も発生する。
- **出力は必ず「下書き」として提示し、講師の確認・編集を経てから保存する**。AI の出力がそのまま保護者に届く経路は作らない。
